# residual-evolution 残差驱动有限种群概率演化，基础框架

独立实现"残差驱动的有限种群概率演化"新方法的第一版基础框架。
本仓库与旧仓 /home/chuhan/projects 完全隔离，不 import 旧仓任何代码，参考实现直接复制进 tests/reference。

## 方法一句话

当前表与查询目标的残差 e 决定每个合法转移的真实增益 G，熵校准把增益变成方向分布 P，解析步长 h 把方向分布变成一次性抽样核 K，期望损失满足精确恒等式 E[L'] = L - hD + h^2 C。

## 第一版参数决策

1. 候选集直接用全集，每个单行块枚举全部合法状态，不做裁剪。
2. alpha = 0.5，即要求平均增益达到最大可达增益总和的一半。
3. 参考分布 R 保持比例 0.9，其余合法后继均分 0.1。
4. 其余严格按文档设计实现，文档未交代的复杂板块一律最简实现，代码注释标明"最简占位"。

## 配对板块，自动发现需要联合更新的行对

按补充设计文档第二部分实现，配对依据是修改影响互相补偿而不是记录相似。
每行从菜单挑至多 4 个方向各异的代表动作，负分动作只要方向组空着照样入选，
按查询编号加方向建登记本，相反方向检索搭档，每行至多 8 个加 1 个随机搭档，
每对拼至多 16 个联合动作，交换 8 即互换两行某字段的值，组合 8 即两边代表动作搭配，
配对评分 Gamma 为联合支持最大增益减两个单行最大增益，正分对贪心绑定至多 32 对，
双行块完整保留两边全部单边动作，块内联合抽样块间独立，引擎数学零改动。
触发时机为冻结重试轮，平时纯单行菜单，卡住即上一轮整张菜单无一正增益动作。
锚点测试，文档例 Gamma 恰为 0.5 逐位对上，打乱行序仍自动找回补偿对。

test_300x10 实测，配对把 2.0 死角打到三种子 0，0.5，0，
两个种子 50 查询全对，另一个剩单查询差一，
其修复需要三行以上循环补偿，是双行块的真实边界，如实记录。

## 重复记录压缩与查询依赖索引，大规模数据的两级加速

按补充设计文档第四部分第六条与第二条实现，面向重复行多的大表。
相同状态的行菜单增益与倾斜概率完全相同，压缩后每组只算一次，
M 与 D 按重数加权，跨行交互 C 的总漂移为重数加权和，自交叉扣除同样加权，
期望损失恒等式在加权矩下逐字成立，测试里对多项计数完整枚举精确对上。
抽样绝不用一个共同开关让组内行一起变，按多项分布抽各后继的数量，
这与组内每行独立按同一核抽样精确同分布，方差与跨行相关性都不变。
查询依赖索引给每条查询记下依赖字段，编辑注册只重算受影响列，
未涉及列直接从来源行复制，与全量求值逐位一致，随机两百例对拍全过。
卡住时配对板块回退行级菜单与行级核，慢一轮不影响正确性。

合成重复表基准，16200 行 300 种状态 50 查询，
每轮 24.0 秒降到 3.9 秒，约 6.1 倍，两版首轮损失逐位一致，
test_300x10 分组加配对端到端照常归零。

## 组核矢量化与稀疏化，消灭逐组小数组开销

分组后热点变成几千次逐组小 numpy 调用，三步改成拼接大数组一次算完。
第一步熵校准平铺，所有组的增益拼成一条长数组配段偏移，
共享 beta 二分用分段 logsumexp，maximum.reduceat 加 add.reduceat 实现，
与逐块二分同括根同轮数，随机例相对误差 1e-9 内一致。
第二步查询条件预编译成算子码与字段下标，注册求值不再做字符串分发与线性查找，
菜单规范化改为保序 unique 加首现排序，与字典去重逐项一致。
第三步核构造不再物化几亿元素的增量大矩阵，
增益的线性项用势能差，phi 等于特征矩阵乘加权残差，一次矩阵向量积，
二次项只依赖状态对与固定权重，跨轮字典缓存，权重不变时永不过期，
漂移用稀疏矩阵乘特征矩阵，源行泄漏率单独扣除，
keep_deltas 开关保留显式路径供测试对拍，缓存复跑逐位不变有测试把守。

累计效果，合成重复表基准每轮 24.0 秒降到 0.4 秒，约 60 倍。
nltcs 同形状合成基准，16181 行 16 二值字段 1001 条二三阶查询，
每轮 2.1 秒降到稳态 1.07 秒，40 轮损失 192 万降到 2.1 万。

## 懒注册与按字段批量菜单，候选不再进注册表

宽表低重复数据（plants 形状 17412 行 69 字段）暴露两个新病根，
每轮几十万候选逐个 register_edit 的 Python 调用开销占八成，
且候选全部注册导致状态数与特征矩阵无界膨胀，五轮即上百万状态。
第四刀把候选改成差分表示彻底绕开注册，batchmenu 加 batchkernel 两模块。
候选编辑记为组号加至多三个改动字段与新值编码，答案差只在改动字段依赖的查询上非零。
条件计数分解，每条查询按涉及字段拆成条件组，域值通过表预先算好，
候选的答案差由通过组数的增减整型判断还原，特征等价性有逐位对拍测试。
状态级条件计数用注册表级增量缓存，值编码本同步扩容。
单字段候选占多数，行内列下标天然有序，直构 CSR 不触发排序不需合并，
多字段候选走坐标格式合并，漂移聚合用组乘查询数的整数键 bincount 稠密累加。
熵校准二分加提前退出，区间相对宽 1e-13 或中点撞端点即停。
增益漂移交互步长的数学表达式与组核逐项相同，
批量核与组核同菜单全指标对拍 1e-9 内一致，抽样按二项加条件多项精确分解，
只有抽中落地的状态才注册，每轮新增状态数不超过实际改动行数。

效果，plants 形状每轮 11.8 秒降到 1.15 秒约 10 倍，
注册膨胀治住，20 轮只新增 5767 状态，此前组路径 5 轮就 130 万。
nltcs 形状每轮 1.07 秒降到 0.74 秒，test300 批量路径归零对账全过。

## 冻结重试提速三刀，批量注册，配对矢量化，配对退避

新考卷跑一遍约 110 秒，剖析发现批量快路径只占 20 秒，
冻结重试轮的行级配对路径占 135 秒，三个病根各挨一刀。
刀一批量注册，特征化改为按字段整理等值条件清单与半空间分数表清单，
每个取值缓存命中条件数向量与分数向量，新行按字段查表累加一次出特征矩阵，
register_many 对新键按首次出现顺序发号，与逐个注册编号逐位一致，
编辑菜单与配对的注册全部改走批量，几十万次逐行 Python 特征化归并为矩阵运算。
刀二配对矢量化，原来牵线约 2700 对逐对拼联合动作逐个注册打分最后只绑 32 对，
改为素材先收集再统一批量注册，全部联合动作平铺成矩阵一次算增益，
交叉项走元素积矩阵乘，分组取最大用 reduceat，空组置零后与零取大，
每行单边动作的增量与增益同样平铺一次矢量化。
刀三配对退避，平台期 60 次重试每次全量重建菜单加配对约 50 秒无用功，
冻结连击前三次照常配对，之后每四次配对一次，其余走便宜的批量菜单刷新，
--pairing-backoff 参数控制，取 1 完全等价旧行为，默认 4。

位一致实证，退避取 1 复刻旧语义跑种子 1，
终表 sha256 与提交在案的官方表逐位一致，前两刀纯加速零数学改动。
退避取默认 4 后重试期轨迹改变属预期语义，三种子重跑，
耗时 111，95，128 秒降到 39，56，39 秒约 2.5 倍，
综合误差分 0.0804 变 0.0802，质量持平提速白赚。

## 熵校准布伦特法与核组装省功，第六刀

第五刀后剖析 plants 形状基准，每轮 1025 毫秒里熵校准全量指数扫描占两成，
核组装的稀疏矩阵搬运占四成，两处各挨一刀，全程不改方法语义。
刀一求根器换代，原二分法每轮约 65 次全量扫描百万级候选，
换 scipy 布伦特法同容差求根，区间保证收缩且超线性收敛，扫描次数减半，
根可能落在约束下侧，至多八次乘一加四千分之一万亿向上微推到达标一侧，
保持取上端点语义，评价函数改无移位指数，中心化增益全体非正天然无上溢，
再加括根热启动，evolve_batch 持有上一轮的根作下一轮出发点折半或翻倍，
翻倍串从头数起变成一两步到位，每轮评价次数再减半。
中途试过安全牛顿反而更慢，终止判据靠区间宽度而牛顿只从一侧逼近，
区间不缩退化成交替二分还多算导数，教训是区间容差场景当用布伦特法。
刀二核组装省功四件，答案差矩阵九成条目是零，先过滤零条目再建稀疏矩阵，
去掉精确零加项逐位不变，下游矩阵向量积与漂移聚合规模降一个量级，
嵌套花式索引提升为先取组号数组再按行取，布尔差先走八位整数再落双精度，
增益平方阵共享下标结构只换数据不整块拷贝，
coo 转 csr 已自动合并排序，冗余的显式合并去掉。

实证三层，先做刀二时种子 1 退避 1 终表 sha256 前缀与官方表一致逐位零改动，
合入刀一后布伦特根与二分根在容差内一致但末位可能不同，
三种子重跑终表与提交在案的官方表逐字节一致，
阅卷综合分 0.080426，0.078587，0.081512 一字不差，轨迹实证未变。
耗时三种子 39，56，39 秒降到 36，52，36 秒，
形状基准 nltcs 每轮 439 降到 372 毫秒，plants 每轮 1025 降到 710 毫秒。

评价方案拍板，无噪声阶段报训练卷分数并加保留卷把关泛化，

## 评价指标，严格按 AIM 与 GSD 文献定义

AIM 式，McKenna 等 VLDB 2022，workload 取全部 k 阶边缘表，
单边缘误差为边缘计数表 L1 距离除以行数，对 workload 平均。
GSD 式，Liu Vietri Wu ICML 2023，统计查询按比例口径，报平均与最大绝对误差。
评价与生成严格分离，保留查询只进评价脚本，加载时强制校验与生成查询语义零交集。

旧 50 题考卷三种子实测，随机基线到演化终表，
GSD 式 measured 50 平均误差 0.0710 降到 0.0005，最大恰为一行计数 1/300，
GSD 式 heldout 1024 平均误差 0.0128 降到 0.0067，没见过的三四阶查询误差近乎减半，
AIM 式全部二阶边缘平均 0.662 降到 0.296，全部三阶边缘平均 0.981 降到 0.610，
被查询覆盖的结构打满，未覆盖边缘的改进有限，与查询驱动的机理一致。

综合误差分把四组子指标统一到 0 到 1 后等权平均，越小越好，
GSD 两组本身是比例误差，AIM 两组除以 2 恰为总变差距离 TVD，
四组各占四分之一，拟合，泛化，二阶结构，三阶结构，
真实表自评恒 0，随机基线 0.2263 ± 0.0022，演化终表 0.1150 ± 0.0008，误差近乎减半。

## 文献基线对照，PGM 与 GSD 零噪声同餐

跑法，两家只吃考卷里 548 条全二阶答案加边缘化出的一阶，半空间题它们的官方接口吃不了，
AIM 底座 Private-PGM 用官方 mbi 的 MirrorDescent 一次性拟合图模型再抽 300 行，
完整 AIM 的自适应选题在零噪声下无意义，文献对照即这种一次性喂全二阶，
GSD 用官方 private_gsd 库默认参数遗传搜索，同餐断言逐格核对喂料等于考卷答案，
脚本 scripts/run_baseline_pgm.py 与 run_baseline_gsd.py，借第三方库环境运行，
命令写在各自文件头，输出表与我们同一套 eval_test300.py 阅卷，age 箱内还原同一策略。

三种子平均成绩，指标依次是 measured，heldout，其中半空间，AIM 二阶，AIM 三阶，综合分。
随机基线 0.0455，0.0257，0.0856，0.662，0.981，0.223。
PGM 0.0079，0.0069，0.0194，0.113，0.247，0.0935。
GSD 0.0025，0.0059，0.0158，0.083，0.233，0.0810。
本方法 0.0015，0.0059，0.0166，0.085，0.228，0.0802。

结论三条。
本方法与 GSD 综合分打平，边缘轴在种子噪声范围内不分伯仲，
measured 轴本方法明显更低，因为考卷里 150 条高阶与半空间题只有本方法吃得下。
两家表空间方法都明显优于 PGM，PGM 分布层面把边缘拟到残差 0.01 个计数，
但抽成 300 行小表时离散化损失吃掉精度，二阶计数平均偏 2.2 个，小表场景是表空间方法的主场。
PGM 拟合约 14 秒，GSD 搜索约 9 秒，本方法第六刀提速后约 41 秒，速度暂不占优后续再优化。

## plants 真数据首战，全二阶考卷与 GSD 同餐对照

数据，UCI plants 的 train 切分 17412 行 69 个 01 字段进仓 data/plants，
attr_1 在该切分内是常值，值域按实际大小处理。

## GPU 后端与惰性特征注册，第七刀

plants 规模 CPU 每轮 6.15 秒对 800 轮要一百多分钟，批量核整轮搬上 GPU，
独立后端 gpukernel.py 用 cupy 实现，CPU 数值路径一行不动，evolve_batch 加 backend 参数切换。
静态量查询结构目标权重上传一次，条件计数每轮在卡上重算不跨轮缓存省掉数 G 显存增长，
残差由条件计数重构特征得出，整数数据下与 CPU 逐位相同，不传大特征矩阵，
抽样注册菜单生成留在 CPU，随机流语义零改变，概率下传后按原语义截断归一。

确定性三原则，浮点聚合不用原子加，分段归约用自写 CUDA 核一段一线程块定序树规约，
归约顺序只由块宽决定与数据无关，同种子同卡两遍逐位相同有测试把守，
漂移合并用键排序加游程求和，段最大与顺序无关逐位精确，整数合并用 int64 前缀差分精确。

三个踩坑记录，cupy 的 maximum.at 对双精度是非原子实现有竞态丢值不可用，
前缀和差分求浮点段和在真数据规模有灾难性相消丢 12 位有效数字触发步长约束报错，
凡浮点段和一律不过前缀差分，repeat 不支持数组重数用 searchsorted 展开代替。

惰性特征注册表配套，GPU 模式整轮不读注册表特征，set_lazy_features 开关默认关，
惰性下注册只发号记元组，编号次序与急切路径一致，build_workload 入口分块矢量化补算逐位相同，
终点损失在卡上由条件计数直接算免物化，省掉每轮六千行特征拷贝与十几 G 内存增长。

实证，plants 种子 1 前 30 轮 GPU 与 CPU 官方曲线损失逐位一致抽样表完全没漂，
跨后端全指标对拍在容差内咬合，布伦特法对 1e-16 级评估差有放大 beta 容差放宽到 2e-7，
每轮耗时 CPU 6150 毫秒降到 GPU 360 毫秒约 17 倍，剩余大头是 CPU 侧菜单生成，
跑 GPU 前先 nvidia-smi 挑空闲卡用 CUDA_VISIBLE_DEVICES 指定。

## 工作批挑组与步长闸门，第八刀

诊断，后期残差集中少数题而全表每轮全员上场，几百行抢改同一题二阶项互相踩踏，
解析步长被压到千分之五一轮只有约 90 行真动，其余行的菜单增益全是白算。
方案，每轮抽样前按组错位分挑一小批行上场，批外组菜单为空段等价保持概率 1，
错位分是组覆盖的题按绝对加权残差求和，由核顺手回传按状态号记账，
定向额度按分数降序装组，其余名额随机装到 work_rows 行防饿死，
没上过场的新状态分数视为无穷大必入选，冻结重试轮回退全量搜索。
合法性依据，计划在抽样前冻结并按实际菜单求核，期望下降保证不破，
互逆动作增益之和非正故来回拉锯被增益总账天然压制。

步长闸门，早期残差处处大全员上场步长本就顶格，裁组只会自缚手脚，
work_below_step 为正时先全量演化，观测到步长低于阈值才开闸裁组单向不回退。
配套修复，惰性负载模式禁配对回退，行级路径要物化全部历史状态特征，
步长解放后注册可达百万级一次物化即打爆内存，重试只刷全量菜单自救。

实证，plants 种子 1 跑 3000 轮，纯 4096 工作批每轮 158 毫秒但早期吃亏终点 24210，
闸门 0.2 加 4096 的切换版 438 秒跑完终点 17519 比全量 3000 轮的 17920 还低，
墙钟比全量快 2.5 倍，同 438 秒全量只到 42093，后期步长中位从 0.005 放大到 0.024，
阅卷综合分 0.005784 对全量 0.005590 基本持平各轴仍全胜 GSD，峰值内存 2.6G。

## 运行

```bash
# 全部测试，锚点断言、对拍、编辑候选与提供器

# 加重复记录压缩，相同状态行共享计算按多项分布抽样，适合重复行多的大表
./.venv/bin/python scripts/run_test300.py --rounds 400 --retries 60 --grouped --pairing

# AIM 与 GSD 式评价，真实表自评、随机基线与任意合成表对比
./.venv/bin/python scripts/eval_test300.py results/evolved.csv

# plants 真数据，生成考卷，整表演化，阅卷对比
./.venv/bin/python scripts/gen_plants_exam.py
./.venv/bin/python scripts/run_plants.py --rounds 800 --retries 60 --batched --pairing --menu-seed 20260921 --sample-seed 1 --init-seed 1 --out results/plants_curve_seed1.csv --save-table results/plants_seed1.csv
./.venv/bin/python scripts/eval_plants.py results/plants_seed1.csv results/plants_gsd_seed1.csv

# GPU 后端，需 cupy，装法 uv pip install --python ./.venv/bin/python cupy-cuda12x
# 先 nvidia-smi 挑空闲卡，--gpu 须配 --batched，同种子同卡逐位可复现
CUDA_VISIBLE_DEVICES=1 ./.venv/bin/python scripts/run_plants.py --rounds 800 --retries 60 --batched --pairing --gpu --menu-seed 20260921 --sample-seed 1 --init-seed 1 --out results/plants_gpu_curve.csv --save-table results/plants_gpu.csv

# 工作批加步长闸门，早期全量演化，步长低于 0.2 后每轮只挑 4096 行上场
CUDA_VISIBLE_DEVICES=1 ./.venv/bin/python scripts/run_plants.py --rounds 3000 --retries 60 --batched --pairing --gpu --work-rows 4096 --work-below 0.2 --menu-seed 20260921 --sample-seed 1 --init-seed 1 --out results/plants_work_curve.csv --save-table results/plants_work.csv
```

4. 相同后继必须先合并参考质量再倾斜。
