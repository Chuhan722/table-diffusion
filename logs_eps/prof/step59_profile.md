目的：给 乙（稀疏整表项/漂移项）与 甲（重排、少同步）改法留一份改前的逐相基线，
改后用同一脚本（`logs_eps/prof/phase_runs4.sh`）同样的 5 场复测，逐相对照。

## 一、怎么测

- 命令 = 1A 正式命令（`logs_eps/stage1/launch_stage1.sh` 的 run_ours2way 逐字），只改
  `--stop-threshold 0`（禁平台停，恰跑 300 轮）、`--rounds 300`。
- 暖启动场：`--init-table results/stage1/adult_eps{0p1,3}_ours2way_seed1.csv`（1A 收敛表），
  工作批门（`--work-below 0.2`）第 1 轮即开，300 轮全是稳态工作批轮，a/b 各跑一遍看噪声。
- 冷启动场：`--init-avg --init-clean` 从头 300 轮（对照 10-09 剖面 `step56_profile.md` §六）。
- 剖面器 `logs_eps/prof/phase_timer.py`：包住引擎函数前后同步设备，相耗时略偏高；
  结构尺 `temperature_dev` 在 evolve 里 build 之外调用。
- 主机负载：开跑时 load 4→20（别人的 CPU 任务），a/b 差 5% 以内，说明没压到我们的道。
- 远端 CPU：Xeon Gold 6330 @ 2.0 GHz，112 核；同一出菜单本机（高主频）量得 14.5 ms，远端 41 ms，
  单核约慢 2.8 倍，`cpu_side_adult.py` 的本机 CPU 数字不能直接当远端用。

## 三、读数

1. ε=3 一轮 ≈140 ms：GPU build 84（60%）、CPU 计划 48（34%）、结构尺 5、其余 3。
2. 稠密 G×Q 的两处开销合计约 44 ms：整表项 20.5（feats 零填+散射 8.7，两次 gemv 12），
   漂移块里零填 + 两次 gemv + 平方按带宽估 ≈23 ms（差额 45 里的一半，另一半是收益分段和、
   键排序合并等按路径数走的量，ε=0.1→3 路径 26k→105k）。
   这 44 ms 就是 乙 的目标，预计 ε=3 一轮 140→约 100（−30%），ε=0.1 53→约 43（−19%）。
3. 乙 之后整表项只剩 1–2 ms，甲 原打算用它和出菜单重叠的空间基本没了；甲 的余量只剩
   少同步、小核融合，以及 build 内收益/合并链的主机往返，得 乙 完成后再剖一次再定。
4. 出菜单 41 ms 是远端单核慢所致（本机 14.5 ms），不改方法的前提下只能靠 numpy 层面
   的等价重写（逐位相同，属甲）；这块占 28%，是 乙 之后的最大单项。
5. 冷启动 300 轮 162 ms 对 10-09 的 253 ms：各相均约为当时的 0.6–0.7 倍，
   10-09 那次是白天高负载下量的，今后前后对照一律用本脚本同条件复测，不与 10-09 直接比。
6. 正式 1A ε=3 的均值 263 ms/轮 比暖启动稳态 140 高得多：正式跑含门未开时的全菜单轮
   （全菜单本机 142 ms、远端估 400 ms）、重试轮、救援轮与白天负载；提速验收以本剖面
   同条件复测为准，再用 3 种子全程跑看总墙钟。

### 7.2 三刀（`gpukernel.py`，`structure.py`），每刀都与改前逐位相同

1. 直算条目（`_direct_entries`/`_delta_direct`）：一对（路径，边际）一线程的整数融合核 `multi_keys` + `direct_pairs` 代替几十步 cupy 逐步计算；路径单/多字段的分类、分块与条目总量改在主机按菜单 `fields`（左齐规范化：槽 1 空即单字段）用直方图点积算，不再在卡上布尔压缩同步；块内非零计数用 uint64 `add.at` 再按位重解释（`add.at` 不收 int64）。
2. 浮点融合核（`_TILT_KERNEL_SRC`，一律 `__dadd_rn/__dmul_rn/__ddiv_rn` 显式舍入，不受 FMA 合并影响；段归约照 `seg_sum` 的 128 线程跨步串行 + 定序树）：括根评估 `evaluate` 由 ~11 步 cupy 变 2 核 + 点积（`tilt_norm`/`tilt_gain`），缓冲区整段复用；路径增益 `lin − quad/2` 一路径一块（`part_gains`）；漂移合并的键与权一条目一线程直接写进拼接缓冲区（`drift_kv`）。结构尺 `temperature_dev` 的 15 字段逐字段 gather 累加改为一核按字段序顺次累加（`embed_scores`，权重表按字段拼接缓存）。
3. 去同步：`cp.asnumpy(scores_gpu)` 推迟到 build 出口；`unit_rows` 用主机已有的 `grouped.counts` 不再回传 `counts`。

逐位核对：`build_bitcheck.py`/`bitcheck_jia2.sh`——同一轮入参分别喂给新码与 HEAD 旧码（`git show HEAD:src/resevo/gpukernel.py` 导出为 `_gpukernel_old.py`），比对 `probabilities`/`group_scores`/`offsets` 整数组按位与全部标量字段，ε=3 与 ε=0.1 各 300 轮**全部逐位相同**（`bitcheck_jia2_cut2.log`、`bitcheck_jia2_cut2b.log`）；`embed_scores` 核与旧 gather 循环 3 组随机场景按位相同；GPU 跨通路测试 164 项通过。
