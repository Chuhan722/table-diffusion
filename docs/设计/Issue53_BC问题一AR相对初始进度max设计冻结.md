# Issue 53：B+C 问题一 A/R 相对初始进度 `max` 设计冻结

## 1. 本轮只回答什么

上一版 `dual_abs_relative_max` 同时计算绝对误差通道 A 和相对误差通道 R，
但直接比较 `max(A, R)`。实验表明，二者虽然都是无量纲误差率，数值基数仍可
不同；常见查询累计的绝对误差会长期令 A 更大，从而使 R 在大多数复制选择中
失去作用。

本轮只检验一个改动：先把 A、R 分别除以同一次运行的初始值，再取最大值。
零目标查询仍然只进入 A，不同时修改 R 的内部聚合，以便保持单一因果变量。

旧模式 `dual_abs_relative_max` 的公式、随机轨迹、输出和诊断保持不变；新公式
使用新的显式 opt-in 模式 `dual_abs_relative_progress_max`。

## 2. 原始通道

设记录数为 N，查询数为 J，当前查询计数为 \(q_j\)，目标计数为 \(y_j\)，
误差为 \(e_j=|q_j-y_j|\)，正目标集合为 \(P=\{j:y_j>0\}\)。

绝对通道为：

\[
A(q)=\frac{1}{J}\sum_{j=1}^{J}\frac{e_j}{N}.
\]

当 P 非空时，令

\[
\beta_j=\frac{1/y_j}{\sum_{k\in P}1/y_k},\quad j\in P,
\]

相对通道为：

\[
R(q)=\frac{1}{N}\sum_{j\in P}\beta_j e_j.
\]

因此零目标查询进入 A，但不进入 R。这里没有 `floor`、平滑常数、指数、混合
系数或数据集专用阈值。

## 3. 固定的初始参照

对一条完整演化运行，只在第 1 轮之前的初始合成表 \(S_0\) 上计算一次：

\[
A_{\mathrm{init}}=A(q(S_0)),\qquad
R_{\mathrm{init}}=R(q(S_0)).
\]

这两个值随后冻结，所有轮次、所有地址、孤立分数定尺和每个 Gibbs 微步共享
同一对参照。禁止按轮重算，禁止按候选侧重算，也禁止在不同地址上分别重算。

该参照只依赖算法本来已经拥有的公开目标和初始合成表查询计数，不读取原始
私有表，也不是在新数据集上重新调参。

## 4. 新能量与复制分数

当 P 非空且两个初始参照均有效时：

\[
\widetilde A(q)=\frac{A(q)}{A_{\mathrm{init}}},\qquad
\widetilde R(q)=\frac{R(q)}{R_{\mathrm{init}}},
\]

\[
E(q)=\max\{\widetilde A(q),\widetilde R(q)\}.
\]

评价某个复制开关时，0、1 两侧均使用同一对冻结参照：

\[
s=E(q^{(0)})-E(q^{(1)}).
\]

后续仍用既有、单独冻结的孤立分数 RMS 把 s 转成条件 logit；本设计不改变
Gibbs 温度、随机流、扫描顺序或无门控接续规则。

## 5. 零边界规则

不引入任意 epsilon，按语义分别处理：

1. `A_init == 0`：所有查询初始即精确命中。完整演化应在第 1 个扫描前按既有
   精确残差停止；直接构造本模式参照则拒绝，因为不存在需要归一化的进度。
2. P 为空：R 通道结构上不存在，不把 `R_init` 伪造为 1 或 epsilon；能量退化为
   \(E=A/A_{\mathrm{init}}\)，诊断明确记录 R 不适用。
3. P 非空但 `R_init == 0`，且 `A_init > 0`：正目标查询初始全部精确，误差仅来自
   零目标查询。第一版直接拒绝该输入；若继续运行，R 从 0 出发后的相对进度无
   定义，任意 epsilon 都会暗中增加数据尺度相关的超参数。
4. 参照必须是 float64 下的正有限值；不接受 NaN、无穷、负值或布尔值。

## 6. 必须输出的诊断

新模式至少记录：

- `A_init`、`R_init`（不存在时为 null）及参照来源
  `initial_current_before_round_1`；
- 通道聚合为 `max_relative_to_initial`；
- 零目标策略为 `absolute_channel_only`；
- 每次扫描中，候选 0 侧和候选 1 侧分别由 A、R 或平局主导的微步数；
- 两侧同为 A、同为 R、发生 A/R 交叉以及包含平局的微步数；
- 扫描结束时原始 A、R、归一化 A、R 以及最终主导通道。

能量仍使用浮点实际参与 `maximum` 的严格比较。主导诊断单独把相差不超过
8 个 float64 相对机器精度的值记为 `tie`，只为消除 CPU/CUDA 归约次序造成的
末位伪切换；该诊断容差不进入能量、得分、概率或复制选择。

## 7. 实现与回归护栏

- 新模式必须显式传入冻结参照；底层 API 不得偷偷用“当前表”重算初始参照。
- `run_evolution` 只在初始状态计算一次参照，并传给孤立定尺和所有后续扫描。
- NumPy、CUDA eager 和 CUDA batched 使用相同公式，并做 CPU/CUDA 条件值、
  最终 mask、查询计数及轨迹对拍。
- 历史四种权重模式不接收、也不使用新参照；其既有测试与冻结轨迹必须继续
  通过。
- 先完成离线单元/集成验证和结果前协议，再决定是否启动真实 GPU 轨迹。

## 8. 第一版明确不做

- 不修改零目标查询只进入 A 的规则；
- 不拆分 R 的稀有分桶，不改 R 内部的归一化逆目标权重；
- 不增加可学习或可调的 A/R 混合系数；
- 不按数据集寻找阈值来定义“稀有查询”；
- 不重新解释或覆盖上一版 `dual_abs_relative_max` 的失败结果。
