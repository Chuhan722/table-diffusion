# 有限精度采样合同

关联 #83，依赖 #80 / #82 的数值分类与现场保存。采用实用有限精度方案，
不引入概率下限或新的随机位算法；不把理想实数核的正支持当成 NumPy 实现的严格保证。

## 三层数值含义

理想概率、float64 保存的概率向量、底层库实际使用的离散随机过程不是同一层保证。
例如非保持质量 `p=3.700743415417188e-17` 本身可表示，但 `1-p` 舍入成 1，
再算 `1-stay` 就变为精确零。这不是人为按收益符号筛选，也不是用“没抽到”推断零概率。

当前合同标识为 `numpy-finite-precision-v1`。它只检测本次已确认的保持项补数退化：
某段有正非保持质量，而 `1-stay=0`。未检出这个标记不代表不存在其它累计区间、
条件多项分布或有限随机位带来的近似。

## 构核、采样与报告

- 四条构核路径共用检查。若所有具有正非保持质量的段都发生上述退化，
  在采样前报告 `numerical_indeterminate`，保存当前表及完成记录、非零退出；
  不把它叫作本轮没有合法正方向。这里是当前实现的保守数值适用边界，
  不是宣称任何其它采样算法在数学上也无法移动。
- 只有部分段受限时，不中止其它有效移动，不改概率向量；
  通过 `SamplingPrecisionWarning`、核的 `sampling_precision` 和多轮日志报告限制。
  计数按存储段跨轮累加，不是实际搬动行数或独立样本数。
- CPU/GPU 批量共用的采样入口只在补数回算为零且原非保持质量仍正时，
  把已保存的质量传给原 NumPy 二项分布。其余参数按旧算术形成，避免无关重排。
  不缓存可能被调用者修改的概率数组，不用 epsilon 代替质量。
- 行级 categorical 与组级 multinomial 保持原 NumPy 调用；批量路径仍采用原
  二项/条件多项分解。数学上的分解等价，不代表库对任意极小尾部精确实现。
  本步没有实现所有累计区间或库内部的高精度稀有事件抽样。

**恢复正参数可能改变随机流。** 实测 `binomial(n,0)` 与 `binomial(n,2^-53/3)`
即使此次都返回零，后续 RNG 状态也不同。因此发生修复的边界不能冒称同种子轨迹逐位不变；
必须区分未触发边界的正常对照、边界的参数/随机流变化及实际运行结果。

## 产物与错误生命周期

`EvolveResult.sampling_precision` 为可选的逐轮诊断列表；正常返回、冻结、既有早停与
后续数值失败都保留已记录诊断。失败目录在需要时另存 `sampling_precision.csv`，
正常终表仍不会在整体数值中断时发布。

公开 CLI 的 JSON 声明 `sampling_contract` 并给出精度诊断汇总。历史适配器在存在
受限段时明确打印摘要；其曲线末尾增加 `sampling_limited_segments` 和
`sampling_max_limited_mass` 两列，final 行为整场汇总。没有受限记录时曲线格式不变。
请保留这些日志/JSON/曲线，不把单独一张 CSV 当成严格采样认证。

`expected_loss` 和解析上界仍是核公式的数值账本，不是对 NumPy 内部实际分布误差的区间认证。
部分精度受限结果只能按明示的有限精度合同解释。

## 迁移与验收边界

#82 中“预算可约束不可表示的无预算上限”的测试继续保留，预算取 `1e-12`；
原 `1e-100` 的预算虽可产生有限步长，却已超出本次保持/离开表示合同，
改由 #83 的明确数值失败回归覆盖。不是通过放宽测试藏掉这个行为变化。

验证须覆盖整体退化四路径、部分有效两组核、实际二项参数、不受限参数/RNG保持、
正常/冻结/早停与失败现场的诊断保留，以及公开 CLI。普通对拍先检查初表和输入一致；
没有精度边界时要求轨迹/表/RNG相同，若出现已记录边界，须定位首次变化并披露，
不把随机流改变后的结果差异包装成质量或性能提升。

本步不修改查询、目标、参考分布、alpha/stay/damping 或数据依赖停止启发式；
只增加明示的数值失败与报告，不使用真实训练/测试表反馈，也不声明端到端 DP。
