# Issue 53：A/R 相对初始进度历史轨迹离线审计

## 审计边界

本审计只读取上一版 `dual_abs_relative_max` 已冻结的检查点查询答案，以及生成
时本来可用的查询目标；不读取原始参考表，不生成新候选，不做质量评价，也不
搜索参数。独立重算脚本为：
`scripts/audit_issue53_gap_weight_dual_ar_progress_offline.py`。

历史检查点来源：

- `nltcs`：`checkpoint_query_answers.json` SHA-256
  `6159d809ad42d34d109e8b7076a9179af81ee152f1fe74577010e52fc3116bc7`；
- `test_300x10`：`checkpoint_query_answers.json` SHA-256
  `a9b0db3c7c7ccd6c929616f96eebc61c1ca2979d959c86beb3543826acba21aa`。

重算公式与设计冻结一致：

\[
A=\frac{\sum_j|q_j-y_j|}{NJ},\qquad
R=\frac{\sum_{j:y_j>0}|q_j-y_j|/y_j}
{N\sum_{j:y_j>0}1/y_j}.
\]

每个数据集只用 round 0 的历史初始状态建立一次 `A_init`、`R_init`，然后重算
所有历史检查点的 `A/A_init` 与 `R/R_init`。

## 审计结论

上一版不是 R 没有下降，而是 A、R 的初始基数不同，直接比较原始值时 A 几乎
一直更大。若只改变为相对初始进度，历史 `nltcs` 在 round 250 之后的全部冻结
检查点、`test_300x10` 在 round 100 之后的全部冻结检查点都应由 R 主导。

这只证明新坐标能纠正“通道量级遮蔽”，不能证明新动力学的最终质量一定更好；
后者必须按结果前协议生成新的完整轨迹后再评价。
