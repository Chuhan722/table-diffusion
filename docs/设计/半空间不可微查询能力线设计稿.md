## 1. 目的与卖点表述

本项目的关键落点之一是**处理不可微查询**。在标准查询清单（类别边缘、
范围边缘、混合边缘、前缀和、条件前缀和、半空间）中，前五类对 one-hot
概率表示都是线性/可微的——竞争方法（PGM 系、可微松弛系如 RAP）的主场；
**只有半空间查询（w·x ≥ θ 的行数）含硬阈值阶跃**，是文献公认的不可微
代表：

- 梯度方法必须用 sigmoid 等**有偏松弛**才能处理；
- PGM 系则因谓词牵扯全部属性（全阶 clique）**结构爆炸**；
- 我们的演化核只需要行级布尔掩码 `w·x ≥ θ`，**精确处理、零松弛、
  机制零改动**。

当前全部 workload（合取计数）从未覆盖这一层。本线要回答的卖点问题：

> 残差引导演化核能否**直接优化**半空间查询，并**泛化**到未测量的
> 半空间查询？

## 2. 查询定义与生成规则（确定性、可复现）

半空间查询（对二值数据 x ∈ {0,1}^d）：

```text
q(w, θ) = #{ 行 x : w·x ≥ θ }
w ∈ Z^d（整数权重，稀疏或稠密）、θ ∈ Z
```

建议两个难度档（具体数量待拍板）：

- **A 档 row-sum（全 1 权重）**：w = 1（全属性），θ 扫描行重量谱。
  plants 行重量分布集中在某区间，θ 取谱内格点。语义直白
  （"至少 θ 个属性为 1 的行数"）；
- **B 档 一般半空间**：确定性种子生成——权重从 {−1, +1} 均匀抽取
  （或稀疏子集上抽取，子集大小 k 待拍板，建议 k ∈ {8, 16, 32}），
  θ 取该 w 下真实数据行投影分布的分位点（保证目标非退化：
  避开 0 或 N 的平凡值）。

生成器与 workload 文件走现有冻结构造器模式：脚本确定性生成 + JSON
落盘 + SHA-256 钉死 + `--verify-existing` 逐字节复核。目标值从真实表
精确计算（无噪声阶段）。

**measured / heldout 分割**（泛化考核的关键）：同一生成流程产出两份
不相交的半空间集合（分割方式待拍板，建议按种子流直接分批 + 指纹互斥
断言），一份进演化池，一份只做评价。

## 3. 引擎扩展方案（最小改动）

侦察结论（2026-09-05）：`vectorized_eval.py` 自带**算子白名单 + 自动
回退**机制——白名单外的查询整条走旧 `evaluate_table` 慢路径，结果
保证正确，只是不加速。因此分两档实施：

**第一档（必做，保正确）：**

1. `queries.py::eval_query_mask` 增加查询类型分派：
   `query["type"] == "halfspace"` 时按
   `mask = (X[:, attrs] @ w) >= theta` 计算行级布尔掩码；
   合取查询路径逐字不动；
2. `query_fingerprint` 覆盖 halfspace 字段（attributes、weights、
   theta），保证指纹唯一性与互斥断言可用；
3. 向量化路径确认 halfspace 查询进回退组（fallback）且不崩溃——
   fitness / evaluate_table / quality 全部经由行级掩码接口，零改动。

**第二档（选配，提速）：** 半空间的向量化实现本身是一次矩阵乘法
（比合取还简单），若回退慢路径在 6000 轮 GPU 跑中成为瓶颈
（估计每轮增加亚秒级），再按白名单机制补向量化，不影响正确性。

每步配套单元测试：halfspace 掩码与朴素逐行计算对拍；与旧合取查询
混合评价的计数一致性；指纹唯一性。

## 6. 预注册研究问题（无晋级门，diagnostic_only）

- **H1 可优化性**：halfspace_measured 上 R 相对 E 与裸猜基线的改善
  幅度——残差引导对硬阈值谓词是否有效（fitness 行归因在半空间上
  的方向性是否成立）；
- **H2 泛化**：halfspace_heldout 上的表现——引导是否只过拟合进池
  的半空间；
- **H3 无损性**：普通组（measured/heldout/one-way）相对进池前的
  变化——半空间题是否挤占常规质量；
- **H4 难度谱**：A 档（row-sum）与 B 档（一般半空间）分组报告——
  卖点边界在哪一档。
