## 4. 地址内语义与随机性

每个地址继续拥有各自的供体表、参与行、初始复制开关和
`gap_l1_gibbs_rng（新缺口吉布斯随机流）`。批量化只共享显卡算子调度，不共享或改写地址状态。

1. 每个地址先按旧协议顺序消费恰好 `8*K（8 乘以活跃坐标数）` 组“有放回坐标、均匀随机数”；`K=0` 不消费随机数。
2. 地址随机带的初始与终点哈希必须与旧单地址语义一致；批量执行不得额外调用随机数生成器。
3. 变长地址按本批最大微步数填充。填充步的有效位必须为假，不得改变状态、产生轨迹记录或消费随机数。
4. 每个地址内部保持严格微步依赖；第 t 个微步必须读取该地址第 t-1 个微步更新后的完整临时复制组合。
5. 输出顺序必须与输入地址顺序一致。计时和填充量只能作为诊断信息，不能参与概率、筛选或结果分类。

## 5. 数值与新执行身份

查询计数固定为 `int64（64 位整数）`，复制开关固定为 `bool（布尔值）`，误差、分数、对数几率、概率和随机数固定为
`float64（双精度浮点数）`；显卡确定性算法必须开启。物理显卡绑定、禁止自动回退和所有方法参数继续继承旧协议。

批量归约会改变旧单地址算术的浮点末位，因此本文明确覆盖旧协议中“批量大小 1 与正式批量轨迹哈希完全相同”的要求：

- 旧单地址轨迹哈希不得冒充或替代新批量轨迹哈希；二者不同是允许且预期的；
- 对旧单地址资格参考，只要求坐标、随机数、开关决定、最终开关、查询计数和最终表精确一致，逐步有限浮点量绝对差不超过
  `1e-12`，且抽样决定翻转数必须为 0；
- 新正式执行身份由“生产批量实现 + 独立批量审计”共同确定。两者必须使用相同批次划分，并对每个地址的有效微步掩码、
  坐标、随机数、7 个双精度逐步值、3 个逐步布尔值、轨迹 SHA-256、最终开关、查询计数和最终表逐位一致；不使用容差放行；
- 两侧任一非有限值、精确 0/1 条件概率、随机流终点不一致、填充步产生输出或最终完整复算不一致，都使执行无资格。

轨迹仍按每个地址独立编号，微步编号从 0 开始；批内位置和填充步不得写入该地址的微步轨迹哈希。
