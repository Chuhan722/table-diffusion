# 最终核数值后置条件

关联 #82，依赖 #80 的局部增益复核与数值中断现场保存。本步只收口校准之后、
采样之前的数值输出，不实现 #83 的采样支持方案，也不改变停止策略或默认参数。

## 活跃核与真实冻结分开

`M=0` 的给定支持无正方向，仍走原冻结出口，允许 `h=0` 和零改行数。
校准已得到正方向的活跃核则要求：

- 最终步长为正有限数；先应用可行上限、曲率上限、改行预算和阻尼，再检查表示性。
- 最终概率有限且非负，保持项速率为零；逐块使用原 `sum`，拼接路径使用原 `reduceat`。
- 仍使用原 `1e-12` 负保持项舍入容差及原清理方式，不截断或抬高非保持概率。
- 全部非保持质量不能因最终乘法下溢成零；无动作的个别块/组仍允许保持概率为 1。
- 预测损失、解析上界与期望改行数为有限数，活跃核的总期望改行数为正。

检查发生在返回 `ok` 之前。共享实现位于 `resevo.stepsize`，行、组、CPU 批量、
GPU 批量四条构造路径共用；GPU 最终概率本来就在 CPU 上形成，不为这些检查增加设备回传。
不以采样器后续抛出的 `p contains NaNs` 代替构核错误分类。

## 保持步长含义，稳定计算账本

步长公式仍为：

```text
h* = min(1 / max_b, D / (2C))   if C > 0
h* = 1 / max_b                 otherwise
h  = damping * min(h*, Bmax/H) if a row budget is given
h  = damping * h*              otherwise
```

预算可以约束一个未加预算时不可表示的上限，不能在应用预算之前就误拒绝最终可表示的步长。
最终仍为零或非有限值时明确中断，不自动放大预算、阻尼或步长。

原来的 `L - hD + (h*h)*C` 在 `h` 很大而 `C=0` 时可先算出 `inf*0`，
即使最终概率合法、真实期望损失有限，也会得到 NaN。共享账本使用同一恒等式的
因子化表达：

```text
expected_improvement = h * (D - h*C)
expected_loss        = L - expected_improvement
upper_bound          = L - h*D/2
expected_rows        = h*H
```

上界的乘积先将较大的正因子减半，避免先算 `hD` 上溢或先减半极小因子下溢。
只读 beta 网格探针同样使用稳定下降量表达式。
收益、校准、步长取最小值及阻尼的顺序不变，概率生成与抽样顺序不变。
账本的浮点结合顺序有意改变，正常记录的 `expected_loss` 末位可以有非决策差异；
不能把它写成所有诊断逐位不变。验证必须分别核对表/随机流/决策量与该诊断差异。

## 失败与范围

主核无可靠数值结果时抛 `FloatingPointError("numerical_indeterminate: ...")`，
由已有多轮入口附带当前完整表与已完成记录，再由驱动保存失败目录并非零退出。
不返回冻结、不用 `nan_to_num` 或默认零值伪装成功，不写正常终表。

这不是整条浮点计算链的区间认证，也不是任意极小概率的精确采样承诺。
尤其 `stay` 舍入为 1 后的实际采样支持仍属 #83：本步没有改 `sample_next`、
`sample_group_next` 或 `sample_batch_next`，没有增加概率下限或修改随机位消耗。
既有 `loss_plateau` 等启发式及其常量敏感性、给定菜单与完整支持的差别保持原样。
没有引入真实训练/测试表驱动、DP 机制或额外算法阶段。

## 复审修订：只读诊断的数值失败隔离

Review `5679171587` 指出的回归已在 CPU/RTX4090 复现：公开单行三值输入、
目标 `(1,0)`、权重 `(1,200)`、迁移率 `(1e-320,1)`、`alpha=0.5`，
实际主核为 `h=2,K=[0,1,0]`，但额外 beta 网格中某点的 `1/max_b` 不可表示，
旧候选会把诊断错误当作主核失败传播。只读探针不能因此中断有效生成。

现在 CPU/GPU 共用诊断收集器；主核的步长、概率和账本检查位置及强度不变。
诊断仅处理带 `numerical_indeterminate:` 的 `FloatingPointError`：
记录不可用点后继续其他点，无关异常仍传播，不宽泛吞掉编程或设备错误。
网格定标保留原初值、最多200次翻倍及几何网格；上界或定标增益不可表示时明确报告
整个网格不可用，不把 inf/NaN 传入网格计算。有效点的算术和严格大于比较顺序不变。

`BatchKernelResult.probe` 的正常值仍为 `(beta_best, J_best)`，
新增可选 `probe_diagnostics`，多轮保存在 `ProbeRecord.diagnostics`：

| 状态 | 最优值 | 含义 |
|---|---|---|
| 未运行 | `probe=None, probe_diagnostics=None` | 开关关闭或原冻结出口，不新增探针 |
| `ok` | 原二元组 | 未遇数值失败；无正方向点时保留原零下降基准 |
| `partial` | 可用点中的原比较结果 | 部分诊断失败，其余正方向点成功 |
| `unavailable` | `probe=None`，记录中 beta/J 均为 `None` | 没有可靠的最优诊断值，不用零伪装 |

`valid_points` 只统计成功完成步长/下降量计算的正方向点，不含原来跳过的非正方向点。
`unavailable_points` 保存每个失败点的 beta 和原因；beta 本身非有限时存 `None`
并保留原因，不发布非标准 JSON 的 NaN/Infinity。每个受限探针发出一次
`ProbeNumericalWarning`；默认警告策略不中断，调用者显式提升警告为错误时遵循其策略。
诊断最优 beta 不替换实际 beta，不改变表、主记录、停止判据或随机数消费。

正常 `_probe.csv` 和失败目录 `probes.csv` 保留各自既有五列。
只有存在受限诊断时追加 `probe_status`、`probe_valid_points`、
`probe_unavailable_points`，末列为包含 beta/原因的 JSON 数组。
不可用最优值写为空单元格并附状态，不写成零；后续主计算真的失败时，既有数值现场
仍保存此前诊断记录。这不是自动恢复或新的 beta 选择策略。

新增回归还覆盖一个真实的全网格不可用场景：将 `(1,0.001)` 权重整体乘 `1e-320`、
两种后继迁移率同为1、`alpha=0.01`；主核在 beta=0 已满足要求，但诊断饱和上界
不可表示。另以诊断专用故障注入覆盖所有正方向试探点都失败、未知异常必须传播。
这不意味着主核可以跳过非法概率或不可表示步长。
