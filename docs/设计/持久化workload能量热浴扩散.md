# 持久化 workload 能量热浴扩散

## 1. 研究问题

现有最高三阶因子 Gibbs 与整代曲率 Gibbs 都在一代内的 donor-copy mask 上定义
有限温条件分布。每一代开始时，donor、参与集合和初始 mask 都会重新生成；真正跨
微步持续存在的合成表没有一个独立的状态转移核。因此，冻结 proposal 的条件分布、
有限 mask 混合、同步整代更新和长期表状态漂移会混在一起。

Issue #30 的共同状态实验进一步表明，固定曲率的相对收益会随生成阶段反转；但
Issue #24 和 #27 又没有支持固定曲率的同轮数长期优势。继续扫描曲率、参与率或
温度不能回答“临时 mask 是否是错误的扩散状态”这一结构问题。

本阶段研究一个不同层次的候选：以合成表本身作为持久状态，在每个随机扫描微步中
直接从 workload 能量的有限温条件分布重采样一个属性值。目标不是证明 heat-bath
或 Gibbs 这一标准原语本身具有新颖性，而是验证它能否为本项目提供同时具备以下
性质的扩散算子：

1. 相对无向离散扩散具有可证明的期望正向倾斜；
2. 不通过 proposal 排序、拒绝、回滚或 checkpoint 选择得到改善；
3. 有全局表状态上的平稳分布和细致平衡语义；
4. 有限温度下保留真实的反向转移支持；
5. 每个微步立即更新表、查询答案和残差，不重置临时 mask。

该方向与 Diffusion Evolution 用随机扰动和目标引导共同变换总体分布的出发点一致，
但采用离散状态空间上的精确条件转移。离散或混合表格上的 energy-based sampling
也会使用 Gibbs/heat-bath，因此本阶段只把“持久表状态 + workload 能量 + 当前项目
隐私边界内的精确增量实现”视为待验证的项目方法，不提前作通用创新性声明。

## 2. 状态、参考扩散与能量

合成表记为

\[
S\in\mathcal S=\prod_{i=1}^N\prod_{g=1}^A\mathcal D_g,
\]

其中 `N` 是公开记录数，`D_g` 是公开 schema 给出的有限合法域。数值属性在当前
原型中按 schema 的闭区间整数域处理。预定义查询的计数答案为 `q(S)`，无噪声目标
为 `y`。本阶段固定等权平方 workload loss

\[
E(S)=\frac12\lVert y-q(S)\rVert_2^2.
\]

参考扩散 `K_0` 每个微步先从全部 `N*A` 个表坐标中均匀选择
`c=(i,g)`，再从 `D_g` 上均匀重采样该坐标。当前值也在候选域内，因此参考核有
自环。它只依赖公开记录数与 schema。

## 3. 有限温 workload 热浴核

固定除坐标 `c=(i,g)` 外的表状态。对每个 `v in D_g`，令
`S^(c<-v)` 表示把该坐标改为 `v` 的表。逆温强度为 `beta>=0` 时，条件分布为

\[
P_\beta(S_{ig}=v\mid S_{-(ig)})
=\frac{\exp\{-\beta E(S^{c\leftarrow v})/N\}}
{\sum_{u\in\mathcal D_g}\exp\{-\beta E(S^{c\leftarrow u})/N\}}.
\]

实现使用等价的相对收益形式

\[
\log w_v=\beta\frac{E(S)-E(S^{c\leftarrow v})}{N},
\]

再减去最大 log weight 做稳定归一化。共同常数不改变条件概率。

采样后立即把选中值、整数查询答案和当前 loss 更新到新状态。下一微步从新表随机
选择坐标并计算条件分布。loss 只定义转移概率和记录诊断，不执行 generation
acceptance、重试、回滚、早停或 best checkpoint。

### 3.1 参考退化与双向支持

- `beta=0` 时，所有 log weight 为零，条件分布精确退化为 `D_g` 上均匀重采样；
- 对有限 `beta`、有限 loss 和非空有限域，数学上的每个合法值概率严格为正；
- 当前值也有正概率，随机扫描核非周期；任意单元格都能以正概率改成任意合法值，
  整个有限表状态空间不可约；
- 正收益、零收益和负收益值都不设置资格门槛。有限温度允许 loss 暂时上升。

float64 稳定实现若出现指数下溢、非有限 log weight 或概率舍入为零，必须显式失败，
不能用静默概率截断继续声称精确 heat-bath 语义。正式协议要求这类事件为零。

### 3.2 平稳分布与细致平衡

定义

\[
\pi_\beta(S)=Z^{-1}\exp\{-\beta E(S)/N\}.
\]

固定坐标的条件重采样就是 `pi_beta` 的完整条件分布，因此该坐标核满足细致平衡。
坐标选择概率与状态无关，均匀随机扫描是这些可逆核的混合，仍满足

\[
\pi_\beta(S)K_\beta(S,S')
=\pi_\beta(S')K_\beta(S',S)
\]

并保持 `pi_beta`。这里的平稳分布是算法语义，不等于有限微步已经混合，也不保证
固定计算预算下优于现有生成器。

### 3.3 相对参考扩散的期望正向驱动

固定状态与坐标，记条件候选 loss 为随机变量 `E_v`。则

\[
m(\beta)=\mathbb E_{P_\beta}[E_v],\qquad
m'(\beta)=-\frac1N\operatorname{Var}_{P_\beta}(E_v)\le 0.
\]

所以增加有限 `beta` 不会提高同一状态、同一坐标下的条件期望下一步 loss；只要
不同合法值的 loss 不全相同，导数严格为负。这是相对 `beta=0` 参考扩散的方向
保证，不是逐样本单调下降保证。

同一条件分布还满足

\[
P_\beta
=\arg\min_P\left\{\frac1N\mathbb E_P[E_v]
+\frac1\beta\mathrm{KL}(P\Vert U_g)\right\},
\]

其中 `U_g` 是公开合法域上的均匀参考分布。因而正向驱动来自对完整有限温分布的
能量倾斜，而不是后置筛选。

## 4. 精确增量计算

改变一行的一个属性只会改变该行对查询 indicator 的贡献。对候选值 `v`，记

\[
d_v=a(x_i^{g\leftarrow v})-a(x_i),
\]

其中 `a(x)` 是该行对全部预定义查询的 0/1 indicator 向量。则

\[
q(S^{c\leftarrow v})=q(S)+d_v
\]

且在计数残差 `r=y-q(S)` 下

\[
E(S)-E(S^{c\leftarrow v})
=\langle r,d_v\rangle-\frac12\lVert d_v\rVert_2^2.
\]

实现必须由行级 indicator 构造全部候选 `d_v`，用上式得到候选 loss；采样后只
增量更新被选中候选的查询答案。小状态和实际配置测试都要用整表查询重算独立对拍。

## 5. 小状态完整枚举 oracle

固定一个可完整枚举的非加性小例子：

- `N=2`；两个类别属性 `a,b`，合法值均为 `0/1`；
- 三条查询：`a=1`、`b=1`、`a=1 and b=1`；
- 目标计数固定为 `[1,1,1]`；
- 枚举全部 `2^(2*2)=16` 张有序表；
- 检查 `beta=0, 0.7, 1.3`，不根据结果替换强度。

对每个 `beta` 构造完整 `16x16` 一微步转移矩阵，正式语义门禁为：

1. 每行和与 1 的误差不超过 `1e-12`，所有允许的单坐标转移与自环严格为正；
2. 模块条件概率与从完整 `pi_beta` 直接归一化得到的条件分布误差不超过
   `1e-12`；
3. `max |pi_i K_ij-pi_j K_ji| <= 1e-12`；
4. `max |pi K-pi| <= 1e-12`；
5. 图遍历确认不可约，所有状态自环为正；
6. 行级查询增量、增量查询答案、loss 收益恒等式与整表重算误差不超过
   `1e-12`；
7. 条件期望 loss 随三个预定 `beta` 单调不增；用条件方差独立复核解析导数。

枚举 oracle 验证定义与实现，不作为实际生成质量证据。

## 6. 实际配置多种子无接受冒烟

### 6.1 固定协议

- 配置：`test_300x10`，公开记录数 300、公开 schema、预定义 50-query 精确
  target 和公开 1-way marginal；
- 初始化：既有 deterministic marginal 初始化；
- 配对种子：固定 `40..59` 共 20 个，不追加、删除或替换；
- 每条轨迹固定 3000 个单坐标微步，约等于一次随机扫描 sweep，全部跑满；
- baseline：`beta=0` 的公开合法域均匀参考扩散；
- candidate：固定无量纲强度 `tau=1`。对同 seed 初始状态，枚举全部坐标和合法值
  的非零 `gain/N`，以其 RMS 固定 `s0`，整条轨迹使用 `beta=tau/s0`，不逐步
  重新定标；若没有非零项则 `beta=0` 并记录失败门禁；
- 两侧共享同一初始表、每步坐标和每个合法值的 Gumbel 随机量。轨迹分叉后不强迫
  表、条件概率或选中值相同；两侧随机流端点必须一致；
- 唯一算法变量是 `beta=0` 与固定初始 RMS 定标后的 `tau=1`；
- 不使用 donor、参与率、复制 mask、独立变异、曲率、generation acceptance、
  重试、回滚、早停或 best checkpoint；
- 只返回第 3000 微步的当前表。best loss 只能作为离线诊断，不能选择输出；
- 运行时不提供真实训练/测试表路径，不报告联合 TVD；当前仍不是 DP。

初始 RMS 是固定尺度约定，不是强度扫描。`tau=1` 只回答候选是否能进入实际配置，
不作为最优温度或默认值推荐。

### 6.2 主终点与预注册分类

主终点是最后 750 个微步的平均当前 workload loss。通过全部语义门禁后：

- candidate 聚合主终点相对 baseline 至少降低 5%，且至少 14/20 个种子更低：
  `supports_persistent_heatbath_smoke`；
- 聚合降低但不足 5%，或只有 11--13 个种子改善：
  `persistent_heatbath_smoke_inconclusive`；
- 聚合不降，或至多 10/20 个种子改善：
  `persistent_heatbath_smoke_not_supported`。

同时报告 final loss、全轨迹平均 loss、正/零/负实际步比例、正负步幅、改变值比例、
条件期望 gain、查询评价次数和墙钟。不以 60,000 个微步冒充独立样本；统计单位是
20 个 seed，种子级 95% 区间只作描述。

这项比较的 baseline 是候选自身的无向参考扩散，不是当前完整生成器。即使通过，
也只能说明有限温 workload 倾斜在实际配置中产生了持续正向动力学，不能声称已经
优于现有 donor-copy 扩散。

### 6.3 风险与语义门禁

预先记录两个限制表述的风险：

- candidate 全轨迹条件熵除以对应合法域最大熵的微步平均低于 50%：
  `conditional_concentration_risk`；
- candidate 对 loss 严格更差合法值的条件概率质量，全轨迹平均低于 1%：
  `uphill_support_mass_risk`。

严格正概率只证明形式支持；第二项用于区分“数学上非零”与仍有实际规模的反向
扩散。风险不事后替换主分类，但会阻止“保留了有意义探索”的表述。

正式分类前还必须满足：

1. 40 条轨迹全部跑满 3000 微步，初始表、初始 loss、尺度和随机流按 seed 对齐；
2. 每一步选中值的增量查询答案与记录的查询变化一致；每 100 个微步及最终状态用
   整表评价复核整数查询答案，结束后必须从保存轨迹摘要独立审计；
3. 每一步记录的 gain 等于前后 loss 差，最大误差不超过 `1e-12`；
4. candidate 在自身当前状态上的条件期望 loss 不高于同状态 `beta=0` 条件期望，
   最大违反量不超过 `1e-12`；
5. 所有正式概率严格为正、和为 1、数值有限，数值护栏或下溢命中次数为零；
6. 输出记录 commit、完整命令、环境、设备、公开输入哈希、全部种子和逐步 loss；
7. 正式运行要求脚本已经纳入当前 commit，工作树（含未跟踪文件）干净，输出拒绝
   覆盖；
8. 独立读取 JSON 复算每种子主/次指标、配对汇总、风险、分类与输入哈希。

任一语义门禁失败时，只能报告实现或实验失败，不给出算法分类。

## 7. 实现与测试边界

本阶段新增独立纯模块、枚举 oracle、研究脚本和测试，不接入 `run_evolution`，不
修改默认参数。测试至少覆盖：

1. 单行、两行以及含合取查询的手算增量；
2. 类别域和整数数值域的完整合法值；
3. `beta=0` 精确均匀退化、固定随机输入复现和 Gumbel categorical 抽样；
4. 16 状态完整转移矩阵门禁；
5. 当前值、自环、全部候选 loss 相同和 target 已匹配边界；
6. 空表、空属性域、答案/target 错位、负或非有限强度、非法表值和概率下溢；
7. 实际配置短程 CPU 冒烟；
8. `py_compile`、针对性测试、完整 CPU/torch 测试和 `git diff --check`。

正式输出保存在 `outputs/persistent_workload_heatbath/`，不提交 Git。若本阶段通过，
下一阶段另立 Issue 研究查询因子预编译/批量候选增量，以及在同查询评价预算和同
墙钟下与当前扩散演化作长期比较。

关联 Issue #32、#30、#27、#24、#18。
