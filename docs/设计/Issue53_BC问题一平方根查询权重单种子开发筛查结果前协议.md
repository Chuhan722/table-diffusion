# Issue #53 B+C 问题一：平方根查询权重单种子开发筛查结果前协议

## 1. 目的与结论边界

R8 开发筛查已经确认：限制历史相对误差的极端权重能够明显改善 NLTCS 的总体与常见查询，但 `N/7` 平滑过强，导致稀有查询退化，并使 `test_300x10` 已测总体超过安全门。本阶段只回答一个后续开发问题：固定使用平方根目标计数分母，能否同时保留 R8 的常见查询收益并恢复稀有查询保护。

候选是在读取 R8 单种子结果后提出的，因此本阶段仍是开发筛查，不是独立确认或正式方法比较。通过只表示值得另立新种子确认协议；不得据此声称全面优于旧 B+C、独立 B 或因子 B，也不得修改公共默认。

## 2. 唯一候选公式

对第 `j` 条已测查询，固定：

```text
d_j = sqrt(max(target_j, 1))
e_j = abs(target_j - current_j) / d_j
E   = mean_j(e_j)
```

配置身份固定为：

```text
gap_l1_weighting = "sqrt_target_relative"
gap_l1_max_weight_ratio = null
```

`1` 是整数计数的最小非零单位。目标为 0 和 1 的分母都为 1；没有可调 floor、指数、混合比例、最大权重比或按行数缩放参数。

该公式是绝对误差分母 `1` 与纯相对误差分母 `target` 的固定几何中点。它是本阶段的设计选择，不宣称来自当前生成过程严格满足的二项分布或独立同分布定理。

## 3. 唯一算法差量与不变量

只改变 C 缺口核逐查询 L1 项的分母。以下设置沿用已经完成的 R8 筛查并保持不变：

- B 残差方向通道及其 `residual_geometry="relative"`、`residual_geometry_floor=8`；
- `gap_l1_sweeps=8`，每轮精确执行 `8*K` 个 Gibbs 微步；
- `strength=2`、`eta=0.5`、logit clip `30` 与每种权重自己派生的一次性孤立分数 RMS 定尺；
- 数据、查询、目标、边际初始化、开发种子、供体、参与行、后置突变与 RNG 域；
- `tol=+inf`、`max_retries=0`，唯一提案无条件接续，不接受/拒绝、不重试、不回滚、不选择历史最好表；
- P=6 自然工作量自动停止、6000 轮/候选上限、终止时 current 输出与固定检查点记录。

旧 `legacy_relative` 和 `bounded_relative` 的公式、随机扫描、输出与诊断必须保持兼容。平方根模式不得设置 `gap_l1_max_weight_ratio`，也不得把旧模式的整数公共分母精确抵消规则错误用于平方根无理数。

## 5. 结果前目标权重审计

## 6. 生成有效性

两条候选轨迹必须同时完成后才可形成 collection。任一情况统一判为 `execution_invalid`，不得解释质量：

- 提交、协议、runner、输入、参数或旧基线哈希不符；
- 不是唯一平方根候选模式，或出现非空 `gap_l1_max_weight_ratio` / smoothing；
- 诊断没有记录 `gap_l1_target_count_quantum=1`，或实际权重跨度与目标审计不符；
- 不是精确 `8*K` 微步、出现非有限条件值、概率精确为 0/1 或 logit 裁剪；
- RNG、初始化、查询/目标、检查点、停止或 terminal-current 契约漂移；
- 有效行率不为 1、schema 非法、文件缺失、部分 collection 被提前比较；
- 为得到结果而重跑旧臂、改公式、改门槛或选择检查点。

生成 collection 不读取原始参考表或未测查询，不发布质量指标。完整 collection 固定并报告 SHA 后必须先停止；评价需要用户后续单独授权。

## 7. 离线评价与结果前通过门

评价算术、固定目标频率箱、查询阶数、未测查询组和正式 measured normalized L1 全部复用已经独立审计通过的 R8 evaluator 定义。候选/legacy 比值越低越好；legacy 为 0 时，两者都为 0 记 1，只有候选非零则为正无穷并失败。

执行有效后按以下顺序分类：

1. **常见收益保留**：NLTCS 正式 measured normalized L1 必须严格低于 legacy，且 `target_2001_16181` 常见箱必须严格低于 legacy；否则为 `common_mechanism_not_retained`。
2. **稀有保护恢复**：NLTCS `target_0_50` 必须不超过 `1.25 * legacy`，并严格低于既有 R8；否则为 `rare_query_protection_not_recovered`。
3. **跨数据与未测安全**：`test_300x10` 正式 measured normalized L1 不得超过 `1.05 * legacy`，两个数据集的 `one_way_safety` 各自不得超过 `1.05 * legacy`；否则为 `measured_or_one_way_safety_risk`。
4. 全部满足才为 `advance_to_fresh_seed_confirmation`。

所有固定检查点和其他分箱必须完整报告，但不得事后增加门槛、选择最好检查点或更换终表。
