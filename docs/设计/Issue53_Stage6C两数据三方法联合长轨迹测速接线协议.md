# Issue #53：第 6C 阶段两数据三方法联合长轨迹测速接线协议

> 状态：**用户已于 2026-08-27 确认本协议范围；当前只冻结协议，不授权运行。**
>
> 本协议只做短轨迹接线与资源测速，不评价方法效果，不决定正式方法，不修改公共默认核。

## 1. 本步只回答什么

新的 `gap_l1_global_s8（全局剩余缺口绝对误差核）` 已接入现有完整生成循环并通过单轨迹回归，但不同
当前表的完整轨迹没有显卡张量批量实现。正式长实验前只回答：

1. 同一次任务能否完整调度 `test_300x10（小型测试数据）` 与 `nltcs（真实数据）`；
2. 三种方法能否各自复用现有 `run_evolution（完整生成循环）` 正常完成20轮；
3. 物理1号显卡最多同时运行2条独立轨迹时，显存、利用率和墙钟是多少；
4. 新核在完整循环中是否继续满足无门控、最后当前表和 `8*K` 微步身份。

本步不回答哪种方法误差更低，也不据此调核、扫描次数、抽样强度、参与率、突变率或正式随机种子。

## 2. 唯一联合矩阵

```text
数据集顺序        test_300x10, nltcs
方法顺序          factor_b_s8, independent_b_s0, gap_l1_global_s8
测速随机种子      9907
每条最大轮数      20
任务排序          seed -> arm -> dataset
轨迹总数          1 × 3 × 2 = 6
最大并发轨迹      2
```

三组中文含义：

| 方法标识 | 含义 | 因子扫描 | 缺口扫描 |
|---|---|---:|---:|
| `factor_b_s8` | 原始 B 因子吉布斯核 | 8 | 0 |
| `independent_b_s0` | 现行独立 B 核 | 0 | 0 |
| `gap_l1_global_s8` | 新的 B+C 剩余缺口核 | 0 | 8 |

任务必须在读取任一结果前一次性列全。入口不得提供数据集、方法、随机种子、轮数、任务顺序或并发数覆盖；
不得先看 `test_300x10` 的运行或质量再决定是否保留 `nltcs`。

随机种子9907只用于接线与测速，明确排除在未来正式效果随机种子之外。当前建议的正式353--357和2500轮
不属于本协议，不因本协议冻结而自动生效。

## 3. 输入与共同生成设置

`test_300x10` 延续第6A/6B阶段的30条二阶、15条三阶、5条四阶测量 workload（查询集合），不用旧的
25条一阶为主版本；`nltcs` 延续1001条二/三阶测量 workload。

```text
初始化                    marginal（一阶边缘初始化）
设备                      cuda（显卡计算），禁止自动回退
beta / h                  1.0 / 0.8
rho / eta / mu            0.01 / 0.5 / 0.01
距离与供体                geometric，lambda=0.5，尺度不变，fixed alpha=16
现行 B                    relative-f8，强度2，initial_rms 固定参考尺度
整代容差                  +inf（关闭整代接受门）
重试                      0
完整生成早停              关闭；固定尝试20轮
精确零误差                保留现有抽供体前确定性停止语义
主输出                    terminal_current（最后当前表）
```

因子核使用已有等价的预编译 workload 路径；新缺口核使用现有显卡分支。供体、参与行、B 初始开关、突变、
查询评价和状态推进都继续由现有完整生成器完成，不另写第二套流程。

## 4. 无门控边界

六条轨迹全部必须满足：

1. 每轮唯一候选下一表无条件成为新的当前表；
2. 不接受、拒绝、回滚、缩步重试、重抽或选择候选；
3. 不因进入某个误差范围冻结单轮运动；精确零误差只保留生成器已有的确定性整体终止；
4. 运行结束返回最后当前表，不返回历史最好表；
5. `best（历史最好）` 只能作为生成器内部诊断，测速报告不得输出或使用；
6. 新核仍固定8次扫描当量，每轮微步数必须等于 `8*K`；
7. 任一任务失败只使整次测速无效，不能删除失败项后解释剩余结果。

## 5. 显卡与并发

执行时只能暴露物理1号显卡：

```text
CUDA_VISIBLE_DEVICES        1
物理设备 UUID               GPU-a3ed64b7-5f7a-0f95-9913-74fdb2340a02
设备名称                    NVIDIA GeForce RTX 4090
进程内设备                  cuda:0
可见设备数                  1
最大独立工作进程            2
```

必须使用 `spawn（新进程启动）` 隔离随机数和显卡上下文，固定任务顺序并最多同时执行2条轨迹。不得按活跃
开关数、运行速度或中间结果重排任务；不得自适应增加/减少并发；显存不足或显卡算子失败时禁止回退到
中央处理器或单进程续跑。是否以后把正式并发设为1或2，只能根据本次资源与墙钟报告再讨论。

## 6. 允许和禁止输出的内容

测速报告只允许包含：

- 协议、输入、源码、设备和任务身份哈希；
- 每任务开始/结束状态、实际轮数、终止原因、墙钟和每轮墙钟；
- 显存峰值、利用率采样、并发任务数和设备错误；
- 主随机流端点哈希、最后表哈希、最后当前表身份；
- 无门控计数、参考尺度是否建立、新核微步数、`8*K` 恒等式、数值护栏和非有限值计数；
- 六项是否全部完成以及测速是否有效。

测速报告和控制台禁止包含：

- 任一方法的 loss（平方误差）、L1（平均绝对查询误差）或查询级误差；
- 初始、逐轮、最后或历史最好质量值与质量曲线；
- 表格内容、查询计数、查询残差、方法差值、排序、胜负或通过标签；
- 原始源表或留出查询评价；
- 根据质量形成的正式轮数、随机种子、并发或方法建议。

运行期算法仍按既有生成流程使用目标查询；这里的“结果盲”是指测速产物和人工判断不读取/发布质量，
不是改写算法让它看不到自身目标。

## 7. 完整性与资源报告

测速只有在以下条件全部满足时才有效：

1. 6/6个预列任务全部完成，任务地址和返回顺序无缺失、无重复；
2. 输入文件和核心实现哈希与冻结清单一致；
3. 全程只看见指定物理1号显卡，无中央处理器回退；
4. 每条轨迹实际状态推进、终点身份和随机端点可审计；
5. 全部应用轮次为无门控；新核微步恒等式与有限数护栏通过；
6. 输出字段白名单通过，产物中不存在任何禁止的质量字段；
7. 全部结果先写临时目录，完成后一次性原子改名，不覆盖旧输出。

若缺口核轨迹实际推进了至少一轮却全程没有建立正参考尺度，则本次接线没有真正覆盖缺口扫描，测速必须判为无效；只有初始表已经
精确零误差、因而在任何状态转移前按既有语义结束时，才允许没有参考尺度。

资源报告只陈述事实，不自动选择正式设置。完成后再与用户讨论：正式固定2500轮是否可承受、并发应取1
还是2、是否需要进一步优化。不得依据隐藏或公开质量值做这些选择。

## 8. 执行与授权顺序

1. 冻结本文和可执行协议清单；
2. 实现薄执行器，只加载输入并逐任务调用现有完整生成器；
3. 用人工替身测试任务调度、失败传播、字段白名单、设备拒绝和原子输出，不读取两个真实数据集；
4. 向用户报告普通测试结果和预计执行方式；
5. 只有用户再次明确说运行，才检查物理1号显卡并启动这6条测速轨迹；
6. 测速结束只报告第6节允许的接线和资源信息；
7. 用户讨论并确认后，另立正式长轨迹效果协议。

本文确认不等于实现器确认，也不等于运行授权。任何一步都不自动提交、推送、创建拉取请求、修改公共
