# Issue 53：A/R 相对初始进度筛查执行接线协议

## 1. 接线范围

本协议只把已经冻结的 A/R 相对初始进度科学方案接入现有 Stage 6D/6E 采集
设施，不修改科学问题、公式、任务矩阵、停止规则或质量门槛。

真实采集仍未获授权。本轮只允许完成代码接线、测试、`plan` 和只读
`preflight`；不得调用生成器创建候选轨迹。

## 2. 任务与资源

- 唯一 seed：`9908`；
- 唯一方法：`gap_dual_abs_relative_progress_max_s8`；
- 数据集顺序：`test_300x10`、`nltcs`；
- 共 2 条候选轨迹，不重跑任何历史臂；
- 单个本地 RTX 4090 分片，最多 2 个 worker；
- 启动前要求指定 GPU 空闲且软硬件身份与冻结环境一致。

轮数上限、候选预算、P6 自动停止、固定检查点和 terminal-current 语义全部继承
上一版 A/R 筛查。

## 3. 复用的执行设施

接线复用以下已经测试的能力：

- 每个 case 独立、原子写入，并拒绝覆盖已有正式输出；
- 完整 case 可按产物哈希安全续跑，不重复生成；
- 生成输入、代码、协议、GPU 和运行时身份检查；
- 使用 `spawn` 启动 worker，完整验证分片后再合并；
- P6 自动停止适配、固定检查点、最终 current 表及查询答案封存。

采集入口是
`scripts/run_issue53_gap_weight_dual_ar_progress_screen.py`。`plan` 和
`preflight` 均不得调用生成器或创建正式输出目录；`collect` 才可能启动真实
生成。

## 4. 新模式专用护栏

每条轨迹必须核对：

- `gap_l1_weighting` 恰为 `dual_abs_relative_progress_max`；
- 聚合恰为 `max_relative_to_initial`；
- `A_init`、`R_init` 与对应数据集冻结值逐值相等，来源恰为
  `initial_current_before_round_1`；
- 初始参照在顶层运行诊断与每轮扫描诊断中一致；
- 零目标仅进入 A，不使用 floor、平滑、最大权重比或其他新增参数；
- 正目标数量、逆目标归一化常数和正目标权重比与冻结目标审计一致；
- 每轮候选 0、候选 1 以及通道配对的主导计数分别严格合计为该轮 `8*K`
  微步；
- 最终通道值完整，主导标签只能是 `absolute`、`relative` 或 `tie`。

R 主导候选侧次数会按数据集完整汇总。次数为 0 不破坏采集有效性，但会在
后续质量评价中触发 `relative_channel_not_activated`，不能晋级新种子确认。

## 5. 产物与信息隔离

候选输出目录为
`outputs/issue53_gap_weight_dual_ar_progress_max_screen_seed9908_v1`，临时分片目录
使用同名 `_shards` 后缀。正式路径已存在时拒绝覆盖。

采集阶段不读取原始参考表、未见查询、历史质量排名或评价报告内容，也不输出
任何质量比较、方法排名或逐检查点赢家。只有两条候选均完整封存后，才能用
单独的评价入口读取冻结评价输入。

## 6. 授权边界

冻结执行协议哈希只是运行身份，不自行构成授权。真实 `collect` 同时要求：

1. 当前代码、文档、科学协议、执行协议和依赖产物通过 SHA-256 核验；
2. 只读 preflight 全部通过；
3. 用户在协议冻结后再次明确同意启动，并确认完整执行协议 SHA-256。

在满足第 3 项前，任何自动延续都不得启动候选生成。
