# Issue #53 B+C 问题一：R8 有界查询权重单种子配对筛查结果前协议

## 1. 目的与结论边界

本阶段只回答一个开发问题：把 B+C 缺口核的查询单位误差权重跨度从历史相对 L1 的无界数据依赖范围压到最多 8 倍后，是否按预期把误差从常见查询拉回，同时没有不可接受地破坏稀有查询和一阶未测边际。

本阶段不是正式方法比较，也不回答 R8 是否全面优于独立 B 或因子 B。单种子结果只能决定是否值得进入新的五种子确认协议；不能写成正式优势、跨数据集稳定结论或公共默认变更。

本协议只改变问题一的查询误差分母。不得同时修改一阶边际是否进入核、停止器目标、`strength`、温度、扫描次数、初始化、供体抽取、参与行抽取、突变或输出规则。

## 2. 结果前冻结的最小任务矩阵

- 数据集：`test_300x10` 与 `nltcs`，必须同时完成。
- 方法：旧 B+C 权重 `gap_legacy_s8` 与新 R8 权重 `gap_bounded_r8_s8`。
- 开发种子：`9908`。该种子在本协议冻结前没有用于 B+C 权重筛查。
- 每个“数据集 × 种子”必须包含两条方法轨迹，共 4 条轨迹。
- 排序固定为 `seed -> dataset -> arm`；不得先看一个数据集或一条方法的结果再取消其余任务。
- `9908` 只属于开发筛查，不得并入后续正式配对胜率。
- 若筛查通过，后续五种子确认预留 `358--362`；是否执行仍需另立协议和用户授权，不能根据本次结果改选种子。

## 3. 唯一方法差异

两组都启用同一个 B+C 缺口核并固定扫描 8 次：

| 参数 | `gap_legacy_s8` | `gap_bounded_r8_s8` |
|---|---:|---:|
| `factorized_gibbs_sweeps` | 0 | 0 |
| `factorized_gibbs_use_compiled_workload` | `false` | `false` |
| `gap_l1_sweeps` | 8 | 8 |
| `gap_l1_weighting` | `legacy_relative` | `bounded_relative` |
| `gap_l1_max_weight_ratio` | `null` | 8.0 |

旧权重逐查询分母为：

```text
d_old,j = max(target_j, 8)
```

R8 权重逐查询分母为：

```text
N = 当前生成表行数
R = 8
s = max(8, N / (R - 1))
d_R8,j = clip(target_j, 0, N) + s
```

`N / 7` 必须使用 `float64` 真除法，不做整数取整。两种方法各自按自己的分母几何建立首个非零孤立分数 RMS 定尺；允许该派生定尺不同，因为强行复用旧定尺会把权重变化和有效温度变化混在一起。除上述权重及其派生定尺外，完整生成参数必须逐项相同。

同一数据集的两组使用同一个种子、相同初始化算法和相同随机流域。轨迹分叉后，状态依赖的供体和活跃开关数可以自然不同；不得为了维持后续随机带逐位相同而改写生成器。

## 4. 生成、停止与输出

沿用 Stage 6E 已完成的完整自动停止流程：

- `inner_early_stopping_patience_ticks=6`；
- 自然工作量为累计参与复制行数除以数据行数；
- A：平方误差达到 0 时 `fit_target_reached`；
- B：连续 6 个已完成自然工作刻度没有严格刷新历史最好平方误差时 `early_stopped`；
- C：轮数或候选评价达到 6000 时 `resource_cap_reached`；
- 优先级为 A > B > C；
- `tol=+inf`、`max_retries=0`，每轮唯一提案无条件写入；
- 不接受/拒绝、不回滚、不重试、不选历史最好表；
- 所有停止原因都输出停止时的 `terminal current`；
- 固定记录 0、100、250、500、1000、2000、4000、6000 轮中实际到达的检查点，但检查点不得被选择为输出。

两组停止器完全相同，但终止轮数可以因轨迹不同而不同。终点指标回答当前完整流程的实际效果；固定检查点曲线只用于区分“权重方向变化”和“停止时刻变化”，不能事后挑选最好检查点替代终点。

## 6. 离线评价指标

生成阶段不得读取原始参考数据、未测查询或另一条方法的结果。4 条轨迹全部完成并固定 collection 身份后，离线评价才可计算：

1. 已测查询正式 normalized L1：

   ```text
   sum_j |target_j - count_j| / (J * N)
   ```

2. 两种核目标值：每个终表同时报告旧 relative gap 与 R8 gap，用于验证代理目标取舍，不作为通过门槛。
3. 按上述固定目标频率箱的平均绝对计数误差。
4. 按查询阶数的平均绝对计数误差。
5. 既有冻结未测查询组，尤其两个数据集的 `one_way_safety`。
6. 有效行率、schema 合法性、非有限条件数、裁剪命中数、R8 平滑计数、R8 实际权重比、停止原因和实际轮数。
7. 总耗时与每实际轮耗时只作资源诊断，不进入质量分类。

所有候选/旧核比值均定义为 `R8 / legacy`，指标越低越好。若旧核指标为 0，则两者都为 0 时比值记为 1；只有 R8 非零时视为正无穷并失败。

## 7. 预先固定的筛查判定

先判执行有效性。任一任务缺失、身份漂移、有效行率不为 1、出现非有限条件值、出现概率裁剪、不是 `8*K` 微步、R8 模式/上限/平滑计数不符或实际权重比超过 8，统一分类为 `execution_invalid`，不得解释质量。

执行有效后按以下顺序判定：

1. **核心机制支持**：NLTCS 终点正式 normalized L1 必须严格低于旧核，且 `target_2001_16181` 常见查询箱平均绝对计数误差也必须严格低于旧核。任一不满足，分类为 `bounded_weighting_mechanism_not_supported`。
2. **稀有查询保留**：NLTCS `target_0_50` 稀有箱的 `R8 / legacy` 不得超过 1.25。超过则分类为 `common_gain_with_rare_query_regression`。25% 是开发筛查护栏，不是正式优越性阈值；它利用旧核在稀有箱已有的大幅余量，但禁止用无上限的稀有退化交换常见收益。
3. **跨数据与未测安全**：`test_300x10` 终点正式 normalized L1 的比值不得超过 1.05；两个数据集 `one_way_safety` 的比值都不得超过 1.05。任一超过，分类为 `measured_gain_with_safety_risk`。
4. 全部满足时分类为 `advance_to_five_seed_confirmation`。

查询阶数、其余频率箱、检查点曲线和两种代理目标值必须完整报告，但不新增事后门槛。筛查失败后不得自动尝试 R4、R16、混合权重或把一阶边际加入目标；任何新设计都需要新协议。
