# 因子工作负载预编译与批量构造

## 1. 问题与边界

Issue #14 的无接受动力学实验中，8-sweep 因子 Gibbs 每个种子的平均墙钟为
`24.97s`，其中因子构造为 `8.22s`，真正的 Gibbs 抽样只有 `0.444s`。当前构造器
会为每条参与记录创建 recipient-donor 两行 DataFrame，并重新检查、解释全部查询
条件。固定 schema 和 workload 的静态工作被重复执行。

本阶段只优化这一工程路径。baseline 与 candidate 使用完全相同的联合能量、初始
mask、随机扫描 Gibbs 条件式、温度、sweep 数、参与率、donor 机制、变异和随机数
顺序。不会接入标准接受闭环，不改变默认生成器，也不实现选择、测量或 DP 机制。

## 2. 预注册实现方案

### 2.1 显式编译对象

增加由调用方显式创建并持有的不可变工作负载对象，只保存公开且运行期间不变的：

- schema 属性顺序；
- 查询顺序、每个查询的不同属性和条件顺序；
- 去重后的条件属性、算子和值；
- 最高允许因子阶数和用于拒绝错配复用的结构签名；
- 0 到最高阶局部 mask 的只读模板。

不使用模块级或隐式全局缓存。调用方决定对象生命周期；跨轮复用同一对象，跨
schema、workload 或最高阶数错配时明确拒绝。编译对象不包含 target、residual、
recipient、donor、训练表、测试表或任何查询结果。

### 2.2 每轮批量工作

非零 sweep 且存在活跃参与记录时，只拼接这些记录的 recipient 和 donor，并对去重
条件各评价一次。之后仍按原始查询顺序、原始条件 AND 语义和原始 scope 排序为每条
记录构造因子。动态 `residual * weights` 每轮重新计算；相同 scope 的浮点累加顺序
保持不变。模型按行构造、采样后立即释放，避免把整表所有因子同时保存在内存中。

Gibbs 仍按升序参与行依次消费独立随机流。批量条件评价和因子构造不消费随机数，
因此合法输入上的主 RNG 与 Gibbs RNG 顺序均不得变化。

### 2.3 退化和异常边界

- `n_sweeps=0` 不编译、不校验也不读取编译对象，继续精确退化到现有定向更新；
- 空参与集和 recipient 与 donor 完全相同时不评价条件、不消费 Gibbs RNG；
- 非零 sweep 继续校验 residual、weights、概率、logit 护栏和 RNG；
- 未知属性、未知算子、缺失操作数、过高活跃查询阶数和编译对象错配必须明确报错；
- 旧的逐行构造器保留为等价性 baseline，不在本阶段删除。

## 3. 一次性正式验证协议

### 3.1 假设、唯一变量和不变量

假设：预编译静态 workload 并批量评价参与行条件，可以在结果逐步等价的前提下显著
降低因子构造与同轮数生成墙钟。

- baseline：`legacy_rowwise`，即 PR #20 当前逐参与行的 Pandas 构造路径；
- candidate：`compiled_batch`，即本设计的显式预编译和批量条件评价路径；
- 唯一变量：因子构造器；
- 两侧都固定为 `test_300x10`、1-way marginal 初始化、精确 50-query target、
  `tau=2`、8 sweep、1000 轮、`rho=0.01`、`eta=0.5`、`mu=0.01`、geometric
  donor 和 `alpha=2→10`；
- 配对种子为 `0..9`；每个 seed 的两种构造器在独立子进程运行，偶数 seed 先跑
  baseline、奇数 seed 先跑 candidate，以平衡固定顺序影响；
- 环境为 `gsd`、CUDA 卡 0；记录 commit、完整命令、Python、NumPy、Pandas、
  torch、GPU、峰值 RSS 和 CUDA 峰值；
- 不读取真实训练表或测试表，不做 loss gate、重试、早停或 checkpoint 选择。

编译耗时计入 candidate 的生成墙钟，同时单独报告。逐轮状态哈希的审计耗时单独
计量并从算法墙钟中扣除；原始含审计墙钟同时保留，避免把审计开销伪装成算法成本。

### 3.2 正确性硬门禁

正式性能结论之前必须全部通过：

1. 小表、真实配置合成状态、三种算子、带/不带 weights 和多轮 residual 上，逐模型
   的活跃属性、因子 scope、邻接、计数完全一致，全部 mask 能量最大绝对误差不超过
   `1e-12`；
2. 10 个正式 seed 的逐轮表 SHA-256、loss、gain、改变单元格数、最终表、方向尺度、
   主 RNG 与 Gibbs RNG 端点全部相同；
3. 除计时和构造器特有计数外，参与行、活跃块、因子数、因子表项和 Gibbs 微步数
   完全相同；
4. 0 sweep 与既有定向路径的表和主 RNG 端点仍精确一致；
5. 新增编译生命周期、错配、空参与集、异常输入、跨轮复用测试，并通过完整
   CPU/torch/CUDA 测试。

任一门禁失败都先判定实现不成立，不报告加速结论。

### 3.3 性能指标与判断规则

主性能指标是每 seed 的“编译 + 运行时因子构造”总耗时；次要指标为扣除状态哈希
审计后的完整 1000 轮墙钟。报告配对种子的均值、中位数、范围、逐 seed 比值和构造
批次数，不用单一 p 值替代效应大小。

预先固定的工程成功标准为：

- 主指标中位数至少降低 50%；
- 完整生成墙钟中位数至少降低 15%，且没有任何 seed 的墙钟变慢超过 2%；
- 峰值 RSS 不增加超过 10%；CUDA 峰值不增加超过 10% 且绝对增量不超过 64 MiB；
- 所有正确性硬门禁通过。

内存阈值任一触发时，即使墙钟改善也只报告时间—空间折中，不描述为无风险替换。
相同轮数结果只说明工程等价和加速，不产生新的算法质量结论。
