# Issue #53 B+C 问题一：A/R 双通道查询权重设计冻结

## 1. 范围与目的

本文仅冻结 C 缺口核的一个新研究模式
`dual_abs_relative_max`，用于检验“稀有查询优先会不会使常见查询变坏”这一个
问题。它是待验证的候选设计，不是已证明的修复。

本次不改 B 残差方向、扫描次数、强度、定尺、概率、RNG、自动停止、
terminal-current 返回或公共默认；不处理 one-way safety、停止漂移或 `8*K`
性能问题。

## 2. 数学定义

记第 `j` 条已测查询的目标计数为 `y_j`，当前计数为 `q_j`，
`e_j = |y_j-q_j|`，表行数为 `N>0`，查询数为 `J>0`，
`P={j:y_j>0}`。目标计数必须非负。

```text
A = (1/N) * (1/J) * sum_{j=1..J} e_j

S = sum_{k in P} (1/y_k)
beta_j = (1/y_j) / S                       (j in P)
R = (1/N) * sum_{j in P} beta_j * e_j      (P nonempty)
R = 0                                      (P empty)

E = max(A, R)
```

A 和 R 的查询权重各自和为 1，外部同样除以 `N`。因此它们都是平均
绝对计数误差率：当通道覆盖的每条查询都错同样的 `c` 个计数时，该通道
等于 `c/N`。

`target=0` 的相对误差没有定义，因此它只以 `|0-q_j|/N`的方式进入
A，不进入 R；不另设 Z 通道。若全部目标都是 0，则 `R=0`、`E=A`。

`floor` 参数只因公共 API 兼容而保留，不进入本模式的任何算式。
`max_weight_ratio` 必须为 `None`。本模式没有可调的 floor、指数、混合比例或
数据集专用尺度。

## 3. `max` 与条件分数语义

对某一微步的关闭/打开两个完整临时状态，分别精确计算：

```text
E0 = max(A0, R0)
E1 = max(A1, R1)
score = E0 - E1
```

先在每一侧内取 `max`，再做差；禁止把它改写为通道差值的 max，也不在通道
切换点增加滞回、epsilon 或随机打破平局。当 `A==R` 时两者给出同一标量
能量；当 `E0==E1` 时分数精确为 0，后续仍使用原条件概率公式。

## 4. 增量状态

为了保留旧模式的浮点结合顺序，新模式复用原主误差数组表示 A，另增
R 的独立数组：

```text
a_term_j = e_j / N
A = sum(a_term) / J

r_weight_j = (1/y_j) / (N*S)   if y_j > 0 else 0
r_term_j = e_j * r_weight_j
R = sum(r_term)
```

设一个坐标只影响查询集 `Q`。对 `b in {0,1}`：

```text
A_b = [a_sum - sum_Q(a_old) + sum_Q(a_b)] / J
R_b =  r_sum - sum_Q(r_old) + sum_Q(r_b)
E_b = max(A_b, R_b)
```

选中一侧后只更新 `Q` 上的计数、条件失败数、指示量与两套误差项/和。
CPU、单任务 CUDA 和逐微步批量 CUDA 必须使用同一定义和 float64。

## 5. 定尺、诊断与兼容性

- 仍用原有“其他开关全为 0”的孤立 `score=E0-E1` 集合，排除精确浮点 0 后求
  RMS；不改 strength、eta 或 logit clip。
- 旧的整数公共分母抵消规则是单个线性加权和专用规则，不宣称支持分段线性
  `max(A,R)`。正式生成路径不向孤立定尺器传该可选精确抵消输入。
- 诊断必须记录模式、`max` 聚合、零目标策略、正目标查询数、逆目标归一化
  常数和 R 内正权重跨度。
- `legacy_relative`、`bounded_relative`、`sqrt_target_relative` 的分母、
  误差项、扫描路径、RNG 消耗和轨迹必须保持兼容；公共默认仍为
  `legacy_relative`。

## 6. 开跑前必须通过的边界测试

1. 公式手算：等误差校准、A 主导、R 主导和两个切换点；
2. `target=0` 只进 A，全零目标退化为 A，负目标失败关闭；
3. 不同 `floor` 不改结果，非空 `max_weight_ratio` 被拒绝；
4. CPU 增量结果与每次全量重算相符；
5. CPU 与单任务 CUDA 的条件值、孤立分数、逐微步状态一致；
6. 单任务 CUDA 与批量 CUDA 的终表、开关、计数和 RNG 终点一致；
7. 旧三种模式的现有冻结测试与轨迹哈希全部通过。

通过上述测试只证明实现符合冻结公式，不证明候选质量更好。
