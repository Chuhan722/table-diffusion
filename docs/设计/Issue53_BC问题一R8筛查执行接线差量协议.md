# Issue #53 B+C 问题一：R8 单种子筛查执行接线差量协议

## 1. 继承关系

本文件只冻结执行接线，不修改
`Issue53_BC问题一R8有界查询权重单种子配对筛查结果前协议.md` 中的任何科学选择。
科学协议 SHA-256 固定为
`50e49ab9786db1dd74476363e0489eeedf76bbdc44a1aa6940a1c7f80e34147e`。

以下项目全部原样继承：两个数据集、旧权重与 R8 两臂、开发种子 9908、
6000 轮/候选上限、P=6 自动停止、八个固定检查点、R8=8、目标频次分箱、
离线查询身份、比值方向、筛查阈值、判定优先级以及结论边界。
执行接线不得通过默认值、别名或报告逻辑改变这些项目。

## 2. 采集接线

- 共四条轨迹，顺序固定为 `seed -> dataset -> arm`。
- 四条轨迹都分配到既有物理 GPU 1（RTX 4090），进程内只可见
  `cuda:0`，最多并行两个工作进程。
- 复用 Stage 6D/6E 已审计的干净工作树、输入身份、GPU 空闲检查、
  spawn 并行、原子暂存、断点恢复、case 清单、终表、检查点向量、
  转移时钟和完整合并设施。
- R8 接线另行覆盖旧设施中写死的“三臂/30 条”配对判断；一个完整配对块
  必须恰好包含 `gap_legacy_s8` 与 `gap_bounded_r8_s8`。
- 同一数据集两臂必须具有相同初始表、初始化后主随机状态、测量查询和目标
  身份。两臂各自建立的 gap 参考尺度允许不同。
- 每个已应用轮次仍必须满足唯一提案无条件写入及 `8*K` 微步身份。
- 旧臂扫描诊断必须是历史 `gap_l1_global_random_scan`，且不得伪造 R8 字段。
- R8 扫描诊断必须记录 `bounded_relative`、上限 8、精确的
  `max(8,N/7)` 浮点平滑量以及不超过 8 的实际权重比。只配置参数但从未
  真正执行一次 R8 扫描，不能作为有效机制筛查。

采集只发布四条完整 case 的结构与资源证据，不读取原始参考表，不发布任一
质量值，也不允许从部分矩阵得出结论。任何既有正式输出均不得覆盖。

## 3. 离线评价接线

评价器只有在用户提供完整 `collection_report.json` 的 SHA-256 后才可运行。
它先验证四条 case、执行提交祖先关系、分片报告、case 清单和所有产物哈希，
然后才加载原始参考表与未测查询。

每个终表和实际到达的固定检查点都复算：

- 已测查询 normalized L1；
- 旧 relative gap 代理目标与 R8 gap 代理目标；
- 结果前冻结的目标计数分箱；
- 查询阶数。

终表另外完整报告既有离线查询组、schema 有效性、多样性和参考支持指标。
筛查分类只使用科学协议已经冻结的五类判定，不从检查点、其余分箱或其余
离线指标增加事后门槛。比值为 R8/legacy；零基线规则保持原协议定义。

评价原子新增 `evaluation_report.json` 与 `screen_metrics.csv`，不重跑生成器，
不选择检查点替代终表。

## 4. 独立审计接线

独立审计器只有在用户同时提供 collection 与 evaluation 两个完整 SHA-256
后才可运行。它不得导入评价器的算术、汇总或分类函数；必须从终表、查询、
参考表和检查点向量重新计算指标、比值和最终分类，并核对 CSV。它不重跑
生成器，也不修改评价产物。

审计通过后原子新增 `independent_audit.json`。审计失败只报告失败，不得据此
重跑某一条轨迹、改阈值或尝试另一 R 值。

## 5. 授权边界

完成并冻结本接线、运行只读 plan、使用人工数据测试和执行只读环境预检，
均不等于授权真实生成。

真实四轨迹采集必须满足以下两个条件：

1. 接线代码已审阅且工作树干净，用户看到完整执行差量协议 SHA-256；
2. 用户在接线完成后另行明确要求开始真实实验，并向采集命令提供该完整
   SHA-256。

当前“继续”只授权完成接线和测试，不授权调用真实生成器。科学协议哈希、
执行协议哈希或一次只读 preflight 都不能单独替代用户的后续明确授权。
评价、审计和后续五种子确认也各自保持原协议规定的单独边界。
