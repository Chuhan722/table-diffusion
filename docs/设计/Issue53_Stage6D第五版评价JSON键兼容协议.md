# Issue #53 Stage 6D（阶段 6D）第五版评价 JSON 键兼容协议

## 1. 固定输入与适用范围

本协议只修正恢复版评价入口对内嵌生成协议的 JSON（结构化文本）键类型比较，不修改已经生成的任何案例、附件、分片报告或完整采集报告。

固定输入为：

- 完整采集报告：`outputs/issue53_stage6d_joint_formal_effect_v5/collection_report.json`；
- 完整采集报告 SHA-256：`f81a18e0ae16726aa99ce4a95882c21d8531a66df35beaf683c738fa7df5771b`；
- 第五版生成协议 SHA-256：`835a2165beebe754707a942ae473bb0432b13ec7c914a1caac7b32a6a1a5a523`；
- 生成提交：`b8bd59f26acc5528165dcb54850f101249563715`；
- 恢复协议 SHA-256：`44527c0a7663a03ac0f5cf54bec11bf22610c3806de84d9cc11b6c6dc0edfbca`；
- 恢复提交：`0562a702fb36a8480d5ed03aac6a7f3733a50ad0`。

## 2. 精确问题

第五版生成协议在 Python（编程语言）内存中使用整数作为两个 `order_counts（阶数计数）` 字典的键：

- `datasets.test_300x10.order_counts` 的键为 `2、3、4`；
- `datasets.nltcs.order_counts` 的键为 `2、3`。

JSON 标准要求对象键为字符串，所以协议随采集报告写出并读回后，这些键成为 `"2"、"3"、"4"`。数值和其他全部字段保持不变。旧恢复版评价器和独立复核器直接比较“读回后的字典”和“内存中的原字典”，因此即使规范 JSON 内容及其哈希完全相同，也会错误报告协议漂移。

结果后的只读诊断已经证明：

- 直接 Python 字典比较不相等；
- 对内存协议做一次标准 JSON 写入/读回归一化后，两者完全相等；
- 报告内嵌协议的规范 SHA-256 为 `835a2165beebe754707a942ae473bb0432b13ec7c914a1caac7b32a6a1a5a523`，精确等于第五版冻结协议哈希；
- 递归差异只有上述两个字典的键类型转换。

## 3. 唯一允许的兼容修正

兼容层必须先自行证明差异恰好是上述两个地址的整数键变字符串键，然后临时向恢复第一版采集验证器提供经过标准 JSON 写入/读回的第五版协议清单。验证结束后必须恢复原函数，不得永久修改任何第一版模块状态。

兼容层禁止：

- 修改采集报告或其 SHA-256；
- 修改、删除、选择或重排30个案例；
- 修改协议字段值、数组顺序、任务顺序、分片归属或参数；
- 宽松忽略未知差异；
- 使用自定义递归字符串化替代标准 JSON 语义；
- 在计划或兼容验证阶段读取原始参考数据、解释质量指标或计算 L1（平均绝对误差）。

归一化后的完整协议必须再次得到第五版冻结协议 SHA-256；否则失败关闭。

## 4. 评价与独立复核复用边界

第二版恢复评价器只替换采集身份验证入口；终表读取、检查点算术、全部 L1、离线查询组、安全指标、五随机种子汇总、逐基线比较和冻结分类继续复用第一版已经冻结的评价算子，不重写指标实现。

第二版独立复核器使用独立采集验证路径，并继续复用第一版独立终表/检查点复算、CSV（逗号分隔表格）复核、汇总和分类算子。它必须额外核对第二版评价器和兼容验证器的源码哈希。

评价与复核均不得重新生成数据、调整参数或消耗新的隐私预算。

## 5. 授权边界

兼容实现和只读计划可以在不访问参考数据的情况下完成。正式离线评价只有在用户同时明确确认以下两项后才允许执行：

1. 固定完整采集报告 SHA-256；
2. 本兼容协议最终完整 SHA-256。

评价完成后再报告评价报告和 L1 CSV（逗号分隔表格）的 SHA-256；独立复核需要用户确认评价报告 SHA-256 后执行。
