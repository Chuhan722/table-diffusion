## 4. 物理 1 号显卡绑定

正式进程必须满足：

```text
CUDA_VISIBLE_DEVICES                精确等于 1
物理显卡编号                        1
物理显卡 UUID（唯一设备编号）       GPU-a3ed64b7-5f7a-0f95-9913-74fdb2340a02
显卡名称                            NVIDIA GeForce RTX 4090
进程内逻辑设备                      cuda:0（唯一可见显卡）
可见显卡数量                        1
```

启动时必须同时核对环境变量、唯一设备编号和名称。设备不可用、身份不符、显存不足或显卡算子失败时立即停止，
禁止自动回退到 CPU（中央处理器）缺口核。

所有随 NLTCS 表规模增长的缺口条件误差、固定参考尺度分数、`8*K` 微步、增量查询计数、最终查询完整复算和
正式独立微步重放必须在物理 1 号显卡上执行。允许 CPU 保留的只有：既有基准组原实现、随机地址派生、
文件读写、稀疏日志、密码哈希和最终精确有理数汇总；这些路径不得代算新缺口核条件式。

## 5. 随机性与显卡数值差量

1. 继续使用上游 `gap_l1_gibbs_rng（新缺口吉布斯随机流）` 的相同 64 位地址和 NumPy
   `default_rng（默认随机数生成器）` 消费顺序。
2. 每个微步仍按“先有放回坐标、后均匀随机数”的顺序形成只读随机带，再一次性移交显卡；显卡批量大小
   不得改变任一地址的随机带或端点哈希。`K=0` 时仍不消费该流。
3. 显卡条件计算固定使用 `int64（64 位整数）` 查询计数、`bool（布尔值）` 开关和
   `float64（双精度浮点数）` 误差/概率，保持上游有序查询、目标函数、对数几率和护栏。
4. 显卡确定性算法必须开启；相同输入在批量大小 1 与正式批量大小下，最终开关、查询计数、表哈希和
   微步轨迹哈希必须完全一致。
5. 结果前接线对拍中，CPU 参考与 CUDA 后端的坐标、随机数、每步开关结果、最终开关、查询计数和表哈希
   必须完全一致；有限 `E0/E1`、分数、对数几率和概率的绝对差不得超过 `1e-12`，且不得造成抽样结果翻转。
6. 正式独立审计必须使用与生产核分离的显卡算术实现；两者全部离散结果必须完全一致，浮点量沿用
   `1e-12` 对拍界。正式运行不得调用 CPU 缺口核形成第二套候选结果。
